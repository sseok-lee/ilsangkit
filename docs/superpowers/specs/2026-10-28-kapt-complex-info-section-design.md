# 부동산 상세 "단지 정보" — K-apt 단지 매칭과 표시 스펙

- 작성일: 2026-10-28
- 단계: 초안 — 사용자 검토 대기
- 선행: #961/#962 K-apt 주간 파일 수집(운영 라이브, `KaptComplex`·`KaptComplexArea`·`KaptComplexParcel`·`KaptSourceFile`)
- 시안: `.superpowers/brainstorm/94638-1793181417/content/complex-info-placement.html` (사용자 선택: C안)

## 1. 왜 하는가

부동산 상세는 지금 실거래만으로 만든다. 단지 자체에 대한 정보(세대수·동수·층수·주차·시공사 등)가 없어 단지마다 화면과 검색 스니펫이 비슷하다. 경쟁 서비스(집품) 분석에서도 단지 기본정보가 상세의 기본 구성이었다.

K-apt 주간 파일로 전국 관리비 공개 의무단지 21,751곳의 정보가 운영 DB에 이미 쌓인다. 이번 작업은 이 데이터를 실거래 상세 페이지와 연결해 사람에게 보여 주고(단지 정보 섹션), 검색엔진에도 넘기는 것(설명 문구·구조화 데이터)이다.

성공 조건:
- K-apt 에 있는 단지의 상세에서 단지 정보가 보이고, 틀린 단지 정보는 보이지 않는다.
- 연결되지 않은 상세는 지금과 똑같다.
- 상세 응답 속도가 눈에 띄게 느려지지 않는다.

## 4. 매칭

### 4.1 근거 (로컬 실측, 2026-10-28)

6개 시군구(강남·구로·해운대·수지·천안 서북·청주 흥덕) 아파트 상세 2,613곳, 거래 30만 건 기준:

| 결과 | 상세 수 | 거래량 비중 |
|---|---:|---:|
| 주소로 1단지 매칭 | 40.5% | 78.8% |
| 이름+연식+번호로 1단지 매칭 | 3.4% | 9.3% |
| 후보 여러 개 (표시 안 함) | 0.6% | 2.7% |
| K-apt 에 없음 (소규모 등) | 55.6% | 9.1% |

이름 매칭 89건을 눈으로 확인한 결과 확실한 오매칭은 1건(우성빌라(백세해운대빌라2차) → 달맞이우성빌라트)이었다. 안전장치 없이 이름만 쓰면 크라운빌Ⅱ(2021)→크라운빌(2015), 센텀리슈빌2단지→센텀리슈빌, 해운대자이2단지→해운대자이 같은 오매칭이 나왔다.

### 4.2 규칙

입력: 상세의 시군구코드(5자리, `bjdCode`), 법정동명(`dongName`), 지번(`jibun`), 건물명, 건축연도(`buildYear`).

1. **주소 매칭** — 지번을 `산여부·본번·부번`으로 파싱해 `KaptComplexParcel(sggCode, isMountain, mainNo, subNo)` 와 일치하고, 그 단지의 법정동이 같은 것.
   - 법정동 비교: 실거래 `dongName` 의 마지막 토큰 = K-apt `dongri`(없으면 `eupmyeon`). 실거래가 "오송읍 서평리"처럼 두 토큰이면 앞 토큰도 `eupmyeon` 과 같아야 한다.
   - 일치하는 활성(`active=true`) 단지가 정확히 1곳이면 채택. 2곳 이상이면 **표시 안 함**(이름 매칭으로 넘기지 않는다).
2. **이름 매칭** — 주소 후보가 0곳일 때만. 같은 시군구·같은 법정동의 활성 단지 중 아래를 모두 만족하는 것이 정확히 1곳이면 채택.
   - 이름 정규화 후 같거나, 한쪽이 다른 쪽을 포함(정규화 이름 3자 이상일 때만 포함 허용)
   - 이름에 들어 있는 숫자 열(단지·차수 번호, Ⅰ~Ⅴ 는 숫자로 환산)이 같다
   - 실거래 건축연도와 K-apt 사용승인 연도 차이가 1년 이하 (어느 한쪽이 없으면 불채택)
   - 정규화: 소문자, 괄호 안 제거, `아파트` 제거, 표기 통일(엘에이치→lh, 에스케이→sk, 아이파크/i'park→ipark, e편한세상/이-편한세상→이편한세상, 플래티넘→플레티넘), 한글·영숫자 외 제거
3. 그 외는 연결하지 않는다.

**도로명 단계 추가 (2026-10-28, 운영 전국 측정 후 결정)** — 순서는 지번 → 도로명 → 이름.
- 도로명 키 = 도로명+건물번호(예: "개포로109길 9"). 실거래는 전월세 거래에 신고된 도로명(합치기 전 전부), K-apt 는 `roadAddress`. 같은 시군구 필지가 있는 활성 단지 중에서 찾는다. 매매 수집은 도로명을 저장하지 않는다(`syncAptSale.ts`).
- 지번 1곳: 채택. 단 도로명이 다른 1곳을 가리키면 표시 안 함.
- 지번 2곳 이상: 도로명 1곳이 그 후보 안에 있으면 채택(예: 개포동 12 — 성원대치2단지→개포대치2단지, 삼익대청→대청), 아니면 표시 안 함.
- 지번 0곳: 도로명 1곳이면 채택하되 이름이 다른 1곳을 가리키면 표시 안 함(실거래 도로명이 이웃 단지로 잘못 신고된 사례: 더샵일산퍼스트월드2단지가 1단지 도로명). 도로명 후보가 여럿이면 표시 안 함. 도로명 후보가 없을 때만 이름.
- 운영 전국 측정(시군구 255곳, 거래 1,447만 건): 연결 거래량 87.0% → 89.7%. 충돌로 미표시 0.09%. 도로명 없는 건물 4.3%(거래 0.14%, 대부분 매매만 있는 소형 건물).

주소 입력은 `getBuildingInfo` 가 돌려주는 `dongName`·`jibun` 을 1순위로 쓴다. 그 지번이 파싱되지 않거나 주소 매칭이 0곳이면, 상세 개요가 쓰는 주소 후보 목록(`realEstateDetailService` 의 주소 후보 조회, #956 합치기 규칙 포함)을 각각 시도해 나온 단지코드가 하나로 같을 때만 채택한다. 그래도 0곳이면 이름 매칭으로 간다.

매칭은 유형(매매·전월세, 아파트·빌라·오피스텔)과 무관하게 같은 규칙을 쓴다. 매매 상세와 전월세 상세는 같은 단지로 연결된다.

### 4.4 계산 위치와 비용

요청 시 계산한다. 조회는 모두 인덱스를 탄다.
- 주소: `KaptComplexParcel (sggCode, mainNo, subNo)` 인덱스 1회 + 단지 PK 조회
- 이름: 같은 시군구 필지 행(인덱스 범위, 시군구당 수백 건) ⨝ 단지에서 같은 법정동만 — 넓은 집계·정렬 없음
- 운영 실측 목표: 엔드포인트 p95 50ms 이하. 넘으면 매칭 결과를 테이블로 미리 계산하는 쪽을 다시 검토한다.

## 5. API

`GET /api/real-estate/:type/complex-info` — 상세 식별자(`bjdCode`, `buildingName`, `buildingKey`)는 기존 상세 API 와 같은 방식으로 받는다.

응답:
```json
{
  "matched": true,
  "matchType": "address",  // address | road | name
  "complex": {
    "kaptCode": "A13580602", "name": "개포경남아파트",
    "householdCount": 678, "dongCount": 9, "topFloor": 15, "basementFloors": 0,
    "useApprovalDate": "1984-03-08",
    "totalParking": 747, "groundParking": 747, "undergroundParking": 0,
    "heatingType": "지역난방", "corridorType": "계단식",
    "builder": "경남건설", "developer": "경남건설",
    "managementType": "위탁관리", "saleType": "분양",
    "elevatorCount": 26, "cctvCount": 102, "evChargerCount": 9
  },
  "areas": [{ "exclusiveArea": 96.98, "householdCount": 166 }],
  "source": { "fileDate": "2026-10-26" }
}
```
연결되지 않으면 `{ "matched": false }` (200). 상세 자체가 없으면 기존 상세 API 와 같은 404.

- 승강기는 `raw` 의 승강기(승객용·화물용·승객+화물·장애인·비상용·기타) 합. 전기차 충전은 지상+지하 설치대수 합. 원본이 비면 null.
- `useApprovalDate` 는 원본 YYYYMMDD → YYYY-MM-DD. 형식이 틀리면 null.
- 응답 캐시는 다른 상세 API 와 같은 정책. 데이터는 주 1회 바뀐다.

## 6. 화면 (C안)

### 6.1 헤더 요약 줄

연결된 경우 기존 요약 줄(`overviewFactsLine`: "N년 준공 · 거래된 전용면적 · 6개월 매매 N건")을 아래로 바꾼다.

`678세대 · 9개 동 · 최고 15층 · 1984년 사용승인 · 단지 정보 ›`

- 값이 없는 항목은 뺀다. "단지 정보 ›"는 상세 섹션으로 가는 링크.
- 연결되지 않으면 기존 줄 그대로.
- 기존 줄에 있던 거래 정보(전용면적 범위·6개월 매매 수)는 대표 시세 영역·가격 흐름에 이미 있어 헤더에서는 빠진다. *(내 판단 — 시안 C 그대로. 둘 다 넣으면 모바일에서 두 줄을 넘는다.)*

바로가기 메뉴에 "단지 정보"를 거래 내역과 위치 사이에 추가(연결된 경우만).

### 6.2 "단지 정보" 섹션

위치: 거래 내역 다음, 위치 앞. 기존 광고 슬롯 개수·위치는 바꾸지 않는다(광고가 연속으로 붙지 않게 순서만 맞춘다).

- 제목 "단지 정보", 부제 "K-apt 공동주택관리정보 · 2026.10.26. 기준"
- 항목 표 (값 없는 줄은 통째로 숨김, 0 은 표시):

| 줄 | 표시 예 |
|---|---|
| 세대수 · 동수 | 678세대 · 9개 동 |
| 층수 | 최고 15층 · 지하 없음 (지하 0 이면 "지하 없음", 있으면 "지하 2층") |
| 사용승인 | 1984년 3월 (42년차) |
| 주차 | 747면 · 세대당 1.10대 (지상 747 · 지하 0) |
| 난방 · 복도 | 지역난방 · 계단식 |
| 시공 · 시행 | 경남건설 · 경남건설 (같으면 한 번만: "경남건설") |
| 관리 · 분양 | 위탁관리 · 분양 |
| 승강기 · CCTV | 26대 · 102대 |
| 전기차 충전 | 9기 |

- 세대당 주차 = 총주차대수 ÷ 세대수, 소수 둘째 자리. 둘 중 하나라도 없거나 세대수 0 이면 세대당은 생략.
- 연차 = 오늘 연도 − 사용승인 연도 + 1 *(내 판단 — 업계 관행 "N년차")*.
- **면적별 세대수 막대**: `KaptComplexArea` 를 전용면적 순으로 정렬해 시작값과 5㎡ 이내인 면적을 한 묶음으로 합친다. 라벨은 반올림 정수 "92~97㎡"(한 값이면 "123㎡"). 묶음이 8개를 넘으면 10㎡ 단위로 다시 묶는다. 막대 길이는 최대 묶음 대비 비율, 오른쪽에 세대수. *(묶음 규칙은 내 판단 — 빌더가 실데이터로 조정 가능)*
- 하단 출처: "출처: 국토교통부 K-apt 공동주택관리정보시스템 · 관리비 공개 의무단지만 제공"
- SSR 로 렌더한다(검색엔진이 읽는 HTML 에 있어야 함). 모바일·데스크톱 모두 같은 표, 데스크톱은 표와 막대를 2열로 둘 수 있다(빌더 재량).

연결되지 않은 상세에는 섹션·메뉴·요약 변경 모두 없다.

## 7. SEO

### 7.1 meta description

`useRealEstateDetailMeta` 의 사실 절(facts)에 단지 숫자를 넣는다.
- 연결된 경우 사실 절: `678세대, 전용 59~84㎡, 1984년 사용승인.` (세대수 → 전용면적 → 사용승인 연도)
- 사용승인 연도가 있으면 기존 "N년 준공"(실거래 신고 건축연도) 대신 쓴다.
- 120자 상한을 넘을 때 빼는 순서(DESCRIPTION_LADDER): 사용승인 연도 → 주변 시설 상세 → 전용면적 → 세대수. 세대수는 단지를 구별하는 숫자라 마지막까지 남긴다. *(내 판단)*
- 앞부분(지역·단지명·거래건수·최근 거래가)은 지금처럼 절대 빼지 않는다.

### 7.2 JSON-LD

`setBuildingPlaceSchema` 에 단지 값을 넘긴다.
- `@type` 이 ApartmentComplex(아파트)면 `numberOfAccommodationUnits` = 세대수.
- 모든 유형 공통으로 `additionalProperty` 에 PropertyValue 추가: 세대수, 동수, 최고층, 사용승인일, 총주차대수 (값 있는 것만).
- 기존 `buildYear` PropertyValue 는 그대로 둔다(실거래 신고 기준).
- 값은 화면 표와 같은 출처·같은 숫자여야 한다.

## 8. 실패·경계 처리

- 단지 정보 조회는 SSR 메인 로더 안에서 다른 요청과 병렬, 실패하면 "연결 안 됨"과 같게 처리한다. 상세 응답 코드·noindex 판정에 영향을 주지 않는다. 짧은 타임아웃(기존 보조 요청 수준)을 둔다.
- `active=false` 단지는 연결하지 않는다.
- 지번이 `가-240`, `BL`, 빈 값처럼 파싱되지 않으면 주소 매칭을 건너뛰고 이름 매칭만 시도한다.
- `KaptSourceFile` 이 없으면(수집 전) 섹션 부제의 기준일 없이 "K-apt 공동주택관리정보"만.
