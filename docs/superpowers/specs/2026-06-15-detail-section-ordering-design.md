## 1. 목표와 제약

### 목표 (우선순위)
1. **SEO · 색인** — 이 URL에서만 얻는 고유 콘텐츠를 위로 올려 크롤러가 고유 가치를 일찍 보게 한다. 단일 h1, FAQ structured data, 내부링크 밀도.
2. **광고 수익** — 스크롤 깊이를 유지해 노출을 늘리고, 헤더 직후 등 고가시성 위치를 보존한다.

> 두 목표는 충돌하지 않는다: "고유 콘텐츠를 위로 + 사용자를 계속 스크롤하게" 가 둘 다를 만족한다. CLAUDE.md 설계 원칙(정보 우선 · 즉시 이해 · 신뢰의 디자인 · 효율적 밀도 · 모바일 네이티브)과도 일치한다.

### 하드 제약
- **광고(AdBanner/CoupangBanner) 개수·위치 유지.** 콘텐츠 섹션만 재배치하고, 광고는 단(tier) 사이에 현재처럼 끼어 있게 둔다. 추가·삭제·표준화 금지. (사용자 정책 — `feedback_adbanner_placement`)
- **섹션 내부 컴포넌트 재사용.** 큰 리라이트 금지. 순서/배치와 "상단 headline 1줄 추가" 수준만 다룬다.
- **order 클래스는 1~12 범위(JIT 안전).** 13+ 금지.
- 단일 h1 불변식 유지 (아래 §3).

## 2. 공통 우선순위 사다리 (Approach A — 확정)

모든 상세페이지는 자기 섹션을 다음 7단에 매핑한다.

| Tier | 이름 | 내용 | 역할 |
|---|---|---|---|
| **T0** | 핵심 정보 헤더 | eyebrow 배지 + 제목(h1) + 핵심 지표 칩 ≤4 + CTA | 즉시 이해 |
| **T1** | 1차 고유 콘텐츠 | 이 URL에서만 얻는 가장 고유한 핵심 데이터 | **SEO 핵심** |
| **T2** | 위치·로드뷰 | 지도+로드뷰 (좌표 있을 때만) | 맥락 |
| **T3** | 2차 콘텐츠 | T1의 근거가 되는 보조/원시 데이터(표 등) | 심화 |
| **T4** | 관련·탐색 | 주변/인근/관련 카테고리/가이드/형제/블로그 | 체류·내부링크 |
| **T5** | FAQ | 구조화 Q&A (FAQPage JSON-LD) | SEO·롱테일 |
| **T6** | 데이터 출처 | DataSourceSection | 신뢰 신호 |

## 3. 불변 규칙 (캐논)

### 3.1 단일 h1
- 렌더된 DOM에 literal `<h1>`은 **정확히 1개**(네이버 등 비렌더 파서의 중복 h1 방지).
- 모바일 전용 헤더(`Mobile*Header`, `md:hidden`)가 literal `<h1>` 소유.
- 데스크톱은 `PageHero`에 `title-tag="div"` 전달 → `<component :is="'div'" role="heading" aria-level="1">` 로 강등(literal h1 아님, 시각·접근성상 최상위 제목은 보존).
- 두 헤더는 `md:hidden` / `hidden md:block` 로 상호 배타 → 어느 뷰포트든 literal h1 항상 1개.
- **금지**: PageHero를 h1으로 승격, Mobile\*Header h1 제거, `title-tag="div"` 누락.
- 적용/재배치 후 E2E 또는 스냅샷으로 `h1 count === 1` 검증.

### 3.2 광고 cadence
- 개수·종류는 현재 페이지별 수준 그대로 고정.
- ① 본문 첫 광고는 항상 **T0 헤더 직후**(폴드 직하단 최고 가시성).
- ② 이후 광고는 주요 콘텐츠 단 경계마다 1개씩.
- ③ 같은 tier 안의 핵심 표 2개를 광고로 끊지 않는다(예: 청약 일정+공급정보, 토지 헤드라인+지목별 → 광고를 두 표 뒤로 한 칸 내림).
- ④ CoupangBanner: 본문/모바일 전용은 FAQ(T5) 뒤·출처(T6) 앞 맨 아래 / 데스크톱 사이드바형은 sticky 별도 컬럼.
- ⑤ 재배치는 콘텐츠 단 순서만 바꾸고 각 광고 인스턴스는 인접 콘텐츠의 order 값을 동반 부여해 "단 사이 끼임" 위치를 보존.
- 배포 후 fill율 모니터링 권장(슬롯 공유 `1878068382` unfill 이슈는 배치와 무관하나 순서 변경 영향 가능).

### 3.3 order 클래스 컨벤션
- `order-N` / `md:order-N` 으로 뷰포트별 순서 분기. **N은 1~12** (13+ 금지).
- 13단 이상 필요 시 끝단(T4/T5/광고/쿠팡/T6)을 `order-12 md:order-12`로 공유하고, 그 그룹은 **DOM 소스 작성 순서**가 곧 렌더 순서이므로 소스에서 의도 순(T4→T5→쿠팡→T6)으로 배치.
- 한 order 스케일은 같은 flex 컨테이너(같은 컬럼) 안에서만 의미 → 데스크톱 좌(article)/우(aside) 2컬럼 grid에서 두 컬럼 항목을 한 스케일로 섞지 말 것.
- **모바일=데스크톱 순서가 같은 페이지(시설)는 order 클래스를 추가하지 말고 소스 순서 자체를 T1 우선으로 재배열**(불필요한 order·JIT 리스크 회피).
- 멀티루트 컴포넌트(DataSourceSection 등)는 class fall-through 불가 → wrapper div에 order 부여.
- 검증 시 Nitro route cache(`.nuxt/cache/nitro/routes`) 삭제 + dev 재시작 필요.

### 3.4 섹션 내부 — headline-first
- 모든 섹션은 **대표 수치/상태 1개를 가장 크게 먼저**(headline), 그 다음 상세.
- 모바일=칩/2열·세로 스택, 데스크톱=그리드/표 확장(같은 컴포넌트 재사용, 컬럼 수만 분기).
- 헤더 칩과 T1 섹션이 같은 수치를 노출하면 차등(헤더=보조지표, T1 headline=대표 수치).

## 4. 페이지별 섹션 순서

각 페이지의 T1(1차 고유 콘텐츠)과 변경점만 요약한다. 광고(현 개수 유지)는 §3.2 cadence 대로 단 사이에 배치.

### 4.1 시설 facility (`pages/[category]/[id].vue`)
- **T1 = DetailFacilityStatus(시설현황)** — 카테고리별 고유 수치 테이블(화장실 칸수, 병원 병상/진료과목, 어린이집 정원, 도서관 장서, 주차 면수, 공원 면적 …).
- 순서(모바일=데스크톱, order 불필요): 브레드크럼+공유 → **T0 헤더** → 광고① → **T1 시설현황 ▲**(현재 기본정보 뒤·광고 2개 뒤 → 헤더 광고 직후로 승격) → 광고② → T3 기본정보·운영시간 → 광고③ → T2 위치·로드뷰 → 광고④ → T4 주변 → 광고⑤ → T4 영상·블로그 → 광고⑥ → (모바일 쿠팡) → T4/T5/T6 가이드·FAQ·출처(DetailContextLinks).
- 데스크톱: 좌 article은 위 순서, 우측 sticky 사이드바에 지도+액션+쿠팡+광고⑦ 유지(T2 사이드바 예외).
- **폴백**: `hasFacilityStatus`가 false인 카테고리(clothes/trash, 빈 pharmacy)는 T1이 비고 기본정보가 자연 폴백 — 빈 섹션+광고 연속 노출 방지 v-if 확인.

### 4.2 지하철 subway (`pages/subway/[slug].vue`)
- **T1 = 역정보** — 노선 색상 배지(환승 포함 dedupe) + 주소 + 운영기관 + 전화. 노선 배지를 섹션 최상단 headline화.
- 현행이 이미 사다리에 거의 부합. 변경: order 클래스 부여 + 노선 배지 headline화 + 데스크톱 사이드바 Actions에 `tel:` 전화 버튼 추가(현재 공유+길찾기만).
- 순서: 브레드크럼+공유 → T0 헤더 → 광고 → T1 역정보 → 광고 → T2 위치·로드뷰 → 광고 → T4 주변 → 광고 → T4 관련탐색 → T5 FAQ → (모바일 쿠팡) → T6 출처. 데스크톱 지도는 우측 사이드바.

### 4.3 부동산 단지 real-estate (`pages/real-estate/[realEstateType]/[city]/[district]/[buildingName].vue`)
- **T1 = 시세 추이 + 요약 스탯그리드** (rent 탭은 **전·월세 거래 비중**을 T1b로 차트 직후 인접).
- 모바일: 대체로 현행 유지(시세추이 이미 헤더 직후). 전·월세 비중을 order-8 → order-5로 끌어올림.
- **데스크톱 = 핵심 변경 (결정 1 확정)**: 위치를 `md:order-4` → `md:order-7~8`로 강등, 시세추이를 `md:order-7` → `md:order-4`로 상향, 거래내역 `md:order-9` → `md:order-6`. 모바일과 정렬, 고유 콘텐츠 우선.
- 끝단(인근단지/주변생활/블로그/가이드/쿠팡/출처)은 `order-12` 공유 유지.

### 4.4 토지 land (`pages/real-estate/land/[city]/[district]/[dong].vue`)
- **T1 = 대지 평당가 헤드라인 카드 + 지목별 시세 그리드.**
- 변경: **＋모바일 헤더 신규 도입**(결정 2), ＋order 클래스 신규, 헤드라인 카드를 첫 광고보다 위로 승격, 둘째 광고를 추이·분포 ↔ 전체거래 사이로 이동.
- 좌표 없음 → **T2(위치) 섹션 없음**, 데스크톱 사다리 충돌도 없음.
- **헤더 CTA = 공유만**(길찾기 비활성) — `MobileDetailHeader`에 directions 숨김 prop 추가(결정 2의 land 보정).

### 4.5 공매 auction (`pages/auction/item/[cltrMngNo].vue`)
- **T1 = 입찰 정보**(감정가/최저입찰가/할인율/유찰·회차/낙찰가율), **T1b = 시세 비교**. AuctionDetailInfo(스펙)는 T3로 분리 강등.
- 변경: ＋모바일 헤더 신규(결정 2), ＋공유 CTA(현재 없음), ＋order 클래스, 상단 `grid` wrapper를 `flex flex-col`+order로 전환.
- 데스크톱 위치(지도)는 단일맵이라 사이드바 패턴 불필요 → 사다리 T2 순서대로 시세비교 뒤(`md:order-8`).

### 4.6 청약 subscription (`pages/subscription/[id].vue`)
- **T1 = 청약 일정 타임라인 + 면적별 공급정보 표.** (임대주택은 전월세 시세가 사실상 가격 T1+.)
- 변경: **＋모바일 헤더 신규**(현재 PageHero가 모바일 폴드 통째 차지 — 결정 2), PageHero에 `title-tag="div"`+`hidden md:block`, ＋order 클래스, 광고②를 일정 직후 → 공급정보 표 직후로 한 칸 이동(T1 두 표 안 끊음).
- 위치는 이미 본문 후반(T2) → 사다리 충돌 없음.

### 4.7 공공임대 public-rental (`components/subscription/PublicRentalDetailView.vue`, 라우트 `pages/public-rental/[type]/[id].vue`) — (결정 3 확정 대상)
- **T1 = 가격 카드 + 스펙 그리드.** 임대유형 가이드·자격·신청 가이드는 공유 템플릿 콘텐츠라 **T3로 강등**.
- 변경: ＋모바일 헤더 신규(결정 2), ＋order, 주변시설을 위치(T2)에서 분리해 인근단지와 함께 T4로, 광고②를 위치 직후 → 교육형 콘텐츠 사이로 이동.
- 모바일 지도 높이 220px 통일 권고(현재 300px — 디자인 인상 변화라 적용 시 확인).
- `announcements/[pblancId].vue`는 콘텐츠 빈약(헤더+variants+관련단지+광고3)으로 경량 보정만: T1=variants 헤더 직후 유지 + matchedComplexes를 T4로.

## 5. 섹션 내부 데이터 배치 패턴 (headline-first)

| 섹션 유형 | 내부 배치 |
|---|---|
| **T0 헤더** | eyebrow 배지 → 제목 → 지표 칩 ≤4(’정보없음’ 필터 후 slice(0,4)) → CTA. 모바일=칩+풀폭 버튼 / 데스크톱=stat 그리드. CTA: 공유 항상·전화 phone조건·길찾기 좌표조건. |
| **핵심 지표 그리드 (T1)** | 대표 수치 1개 크게 → 라벨-값 그리드. 모바일 2열 / 데스크톱 3~5열. |
| **차트+요약 (T1 시세)** | 요약 스탯그리드 먼저(최근평균/최고·최저/전월대비/거래건수) → 차트 아래. rent는 비중 바 차트 직후. |
| **표 (T3)** | 표 위 최신 1건/대표 범위 1줄 headline → overflow-x 표. 모바일 카드형/가로스크롤, 데스크톱 풀 테이블. 합계 tfoot 유지, 중복 컨텍스트 열 숨김. |
| **타임라인 (T1 청약)** | 임박/진행 단계 1개 배지 headline → 세로 TimelineItem 리스트. 상단 요약 1줄만 추가(컴포넌트 재사용). |
| **위치·로드뷰 (T2)** | 모바일=라이브 지도 220px + ’크게보기’ + 로드뷰 220px 세로 스택(mapMedia 상수). 데스크톱: 시설·지하철=우측 sticky 지도(본문엔 로드뷰만) / 부동산·공매·청약·공공임대=본문 2열. 라이브 지도 `md:hidden`은 CSS보다 v-if 분기 권장(카카오맵 이중 초기화 방지). |
| **관련·탐색 (T4)** | 같은 카테고리/형제 카드 먼저(거리 강조) → 교차/주변/인근단지 → 블로그·가이드·지역링크. 모바일 1열 / 데스크톱 2열. NuxtLink 내부링크 밀도. |
| **FAQ (T5)** | 펼친 세로 Q&A 리스트 + **FAQPage JSON-LD 발행**(화면 노출만으론 SEO 가치 없음). |

## 6. 확정된 결정 사항

1. **부동산 데스크톱 통일** — 시세추이↑·지도↓ (모바일과 일치, SEO 우선). ✅
2. **토지·공매·청약·공공임대 4종 모바일 헤더 신규 도입** — `MobileRealEstateHeader`를 `components/common/MobileDetailHeader`로 일반화해 공용화. PageHero는 `title-tag="div"`+`hidden md:block`. land는 directions 숨김 prop로 공유-only. ✅
3. **공공임대 대상 = `PublicRentalDetailView.vue`** (announcements는 경량 보정). ✅
4. **FAQ 전략 = 스키마 통일 + 신설** — FAQ 있는 페이지는 FAQPage JSON-LD 발행 통일, FAQ 없는 부동산·청약에 도메인 공통 FAQ(T5) 신설. ✅

## 7. 범위 밖 / 후속 작업

## 8. 리스크

- **단일 h1 회귀**: `title-tag="div"` 누락 시 이중 h1. 4종 신규 헤더 도입에서 특히 주의 → E2E h1 count 검증.
- **카카오맵 이중 초기화**: `md:hidden` CSS로만 숨기면 DOM 잔존해 맵 더블 마운트 위험 → 위치 분기는 v-if 권장.
- **order-12 공유군 순서**: DOM 소스 순서 의존 → 소스에서 T4→T5→쿠팡→T6 순서 보장.
- **조건부 섹션(v-if) 갭**: 좌표/탭/데이터 부재 시 섹션이 빠져 광고가 연달아 붙을 수 있음(기존과 동일, 회귀 아님).
- **헤더 칩↔T1 수치 중복**: T1을 헤더 직후로 올리면 중복감 — 헤더 칩은 보조지표로 차등.
- **Nitro route cache**: 재배치 검증 시 캐시 삭제 필요.
