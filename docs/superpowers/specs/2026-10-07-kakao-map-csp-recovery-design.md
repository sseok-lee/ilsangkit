# 카카오 지도·로드뷰 CSP 복구 스펙

- 작성일: 2026-10-07
- 단계: 확정 — 사용자 승인 및 Native 로컬 구현·검증 완료 (2026-10-07), 운영 미반영
- 내부 검토: 독립 검토 통과. 타입 검사 도구 가용성 확인 기준 보완.
- 분류: 기존 보안 설정을 보완하는 범위 한정 수정
- 요청: 운영 상세페이지의 지도·로드뷰 장애를 스펙부터 정리해 해결한다.

## 1. 목표와 성공 조건

카카오 CDN 도메인 변경으로 차단된 지도·로드뷰 리소스를 허용하여 기존 상세페이지 동작을 복구한다. 지도 타일 표시, 지도 조작, 촬영 데이터가 있는 위치의 로드뷰 표시를 실제 브라우저에서 확인한다.

사용자 요구는 기존 기능 복구다. 이번 권장 범위는 CSP 수정과 재발 방지 검증이며, 로딩 실패 안내·재시도 UX 개선은 후속 과제로 둔다.

## 2. 확인된 근거

1. 운영 상세페이지에서 `dapi.kakao.com/v2/maps/sdk.js`는 성공했지만, 내부에서 요청한 `https://t1.kakaocdn.net/mapjsapi/js/main/4.5.28/kakao.js`는 `script-src` 위반으로 차단됐다.
2. 스크립트 허용 후에도 `https://t1.kakaocdn.net/mapjsapi/images/json/ext_cr.json`은 `connect-src` 위반으로 차단됐다. 따라서 두 지시어 모두 수정해야 한다.
3. 진단용 브라우저에서만 두 허용 목록을 보완했을 때 지도 이미지 15개가 로딩됐고, 로드뷰 검색·스크립트·파노라마 이미지 요청이 성공했다. 확인한 카카오/다음 요청 46건에는 실패가 없었다. 이는 수정 방향의 근거이며 운영 반영 완료를 뜻하지 않는다.
4. 2026-03-12 커밋 `d7e569427ff96172bb0b6c53b939810de1d54f7b`에서 추가한 CSP에는 `kakaocdn.net`이 이미지에만 허용돼 있었다. 이 날짜는 설정 도입일이며 실제 장애 시작일은 아니다.
5. 카카오는 2026-07-07 공지에서 3분기 내 리소스 제공 도메인 추가와 `*.kakaocdn.net` 허용을 안내했다. 10월 6일에는 도메인 전환 관련 문의와 담당자 답변이 확인된다. 최근 변경과 기존 CSP의 충돌이 장애 발생 시점을 설명하는 유력한 근거다.

- [2026-10-06 도메인 전환 관련 문의 및 답변](https://devtalk.kakao.com/t/kakaocdn-http/151986)

## 3. 접근 방식

| 대안 | 판단 |
| --- | --- |
| `https://*.kakaocdn.net`을 필요한 두 지시어에 추가 | 채택. 공식 권고를 따르고 카카오 CDN 하위 호스트 변경에도 대응한다. |
| `https://t1.kakaocdn.net`만 추가 | 현재 재현은 해소하지만 향후 하위 호스트 변경에 다시 막힐 수 있다. |
| SDK 로더·오류 UI까지 함께 변경 | 이번 차단의 직접 해결에는 필요하지 않아 후속 과제로 둔다. |

## 4. 요구사항

### R1. CSP 허용 범위

`frontend/nuxt.config.ts`에서 공개 페이지에 적용되는 CSP의 다음 지시어에 `https://*.kakaocdn.net`을 추가한다.

- `script-src`: 메인 SDK 및 로드뷰 등 추가 스크립트 로딩.
- `connect-src`: 로드뷰 보조 JSON 등 통신.

기존 `img-src`의 카카오 CDN 허용은 유지한다. 새 허용은 HTTPS로 한정한다. CSP 제거, `*` 또는 단독 `https:`를 통한 전체 스크립트·통신 허용, report-only 전환은 하지 않는다. 다른 보안 헤더와 기존 허용 목록은 유지한다.

### R2. 적용 대상과 호환성

지도·로드뷰가 있는 부동산·시설 상세를 포함해 공통 CSP를 받는 페이지에 적용한다. 상세페이지별 CSP를 중복 추가하지 않는다.

현재 develop의 `baseCsp`와 이를 바탕으로 생성하는 `adminCsp`에서는 공통 수정이 두 정책에 반영돼야 한다. 관리자 이미지 허용 정책은 기존대로 유지한다. 운영 기준 브랜치가 다른 구조이면 그 구조에 같은 두 항목만 반영한다.

카카오 앱 키, API 호출 주소, 지도 중심 좌표, 로드뷰 반경·높이·레이아웃, DB 및 API 계약은 변경하지 않는다. 새 패키지나 환경변수는 필요하지 않다.

### R3. 회귀 검증

자동화 검증은 외부 카카오 응답과 실제 키에 의존하지 않고 다음 보안 계약을 확인한다.

- Nuxt 설정을 읽고 Nitro 라우트 규칙을 합성한 결과에서 대표 부동산·시설 상세의 `script-src`, `connect-src`가 각각 HTTPS 카카오 CDN 와일드카드를 포함한다.
- 기존 `img-src`의 카카오 CDN 허용과 `object-src 'none'` 등 보호 지시어가 유지된다.
- `script-src`, `connect-src`에 전체 허용 토큰 `*` 또는 `https:`가 추가되지 않는다.
- develop 기준 검증에서는 `/admin`, `/admin/**`의 공통 허용과 기존 이미지 정책도 확인한다.

기존 `frontend/tests/server/city-payload-cache.test.ts`의 Nuxt 설정 로딩·Nitro 규칙 합성 방식을 재사용한다. 전체 CSP 문자열 스냅샷이나 원본 파일의 단순 문자열 검색만으로 검증을 끝내지 않는다.

수정 전 새 회귀 검증이 실패하고 수정 후 통과하는 것을 확인한다. Node 20에서 양쪽 패키지 단위 테스트·린트, 프론트 타입 검사·빌드 및 관련 브라우저 검증을 수행한다. 기존 실패나 환경상 실행 불가 항목은 결과에 명시한다.

프론트에는 전용 타입 검사 스크립트가 없으므로 설치된 검사 도구를 먼저 확인한다. 도구가 갖춰진 경우 `npx --no-install nuxi typecheck`를 사용한다. 추가 패키지 설치가 필요하면 자동 설치하지 않고 실행 불가 사유를 기록한다. `npm run build` 결과는 별도로 보고하며 타입 검사 통과를 대신하지 않는다.

### R4. 브라우저 및 운영 복구 판정

CI 검증과 별도로 실제 키가 허용된 HTTPS 환경에서 다음을 확인한다. 운영 복구 완료 판정은 배포된 원본 응답으로 수행하며 진단용 헤더 덮어쓰기는 사용하지 않는다.

| 대상 | 필수 확인 |
| --- | --- |
| 초원그린타운 부동산 상세 — 기존 재현 URL | 문서 응답의 두 CSP 지시어, 지도 타일·마커 표시, 확대/이동, 로드뷰 파노라마 표시·회전 |
| 촬영 데이터가 확인된 시설 상세 1곳 | 공통 컴포넌트에서도 지도·로드뷰 정상 표시 |
| 데스크톱과 모바일 크기 | 상세 직접 진입, 새로고침, 사이트 내부 이동으로 진입할 때 정상 로딩 |
| 네트워크·콘솔 | 카카오 CDN 스크립트·보조 JSON·파노라마 요청 성공, 카카오 리소스 CSP 위반 없음 |
| 새 브라우저 컨텍스트와 기존 방문 환경 | 기존 문서·서비스워커 캐시 때문에 이전 CSP 또는 실패 상태가 남는지 확인 |

로드뷰가 실제로 제공되지 않는 좌표의 안내는 정상 동작으로 구분한다. 지도 SDK 차단으로 인한 빈 지도나 잘못된 로드뷰 미지원 판정은 실패다. 관련 없는 광고·분석 도구 콘솔 오류는 별도로 기록한다.

검증 결과에는 대상 URL, 배포 커밋/릴리스, 응답 CSP, 카카오 요청 결과, 지도·로드뷰 영역 스크린샷을 남긴다. 키 값은 기록에서 마스킹한다.

## 5. 구현 및 배포 경계

예상 코드 변경은 `frontend/nuxt.config.ts`와 보안 회귀 검증 파일이다. 공통 SDK 로더와 화면 컴포넌트는 이번 수정 대상이 아니다.

현재 `develop`에는 운영에 미배포된 제휴 배너 기능이 있다. 긴급 복구를 단독 배포할 경우 운영 `main` 기준 수정 브랜치·PR에 지도 복구 변경만 포함하고, 병합 후 같은 수정과 검증을 `develop`에도 반영한다. 이 복구 때문에 develop 전체를 운영으로 올리지 않는다. main 직접 커밋은 하지 않는다.

스펙 작성과 로컬 검증 완료, PR 준비, 운영 배포, 배포 후 복구 확인을 각각 구분해 보고한다. 운영 배포 후에도 응답 CSP가 오래된 값이면 문서 캐시 계층부터 확인하고 필요한 범위만 갱신한다. 사전 근거 없이 전체 서비스워커·캐시를 삭제하지 않는다.

## 6. 후속 과제

공통 SDK 로더의 타임아웃·실패 후 재시도, 네트워크 오류와 로드뷰 미제공 상태를 구분하는 안내, 카카오 공지 모니터링은 별도 개선으로 다룬다. 이번 복구의 완료 조건에는 포함하지 않는다.
