# 부동산 상세 "건물 정보" — 건축물대장 수집·연결·표시 스펙

- 작성일: 2026-10-29
- 단계: 초안 — 사용자 검토 대기
- 선행: K-apt 단지 정보(#961~#964, `2026-10-28-kapt-complex-info-section-design.md`), K-apt 관리비(#970/#971), 오피스텔 K-apt 제외(#972/#973)
- 확인(recon) 결과: 2026-10-29 대화. 운영 표본 75곳(아파트·빌라·오피스텔 각 25, 강남·서초·분당) 전부 대장 연결.

## 1. 왜 하는가

K-apt 단지 정보는 관리비 공개 의무단지만 있다. 운영 아파트 매매 상세 건물 38,314곳 중 K-apt 아파트·주상복합은 21,206곳뿐이고, 빌라·오피스텔은 거의 없다(오피스텔은 #972 로 K-apt 를 아예 붙이지 않는다). 그래서 소규모 아파트·빌라·오피스텔 상세는 실거래 외에 건물 자체 정보가 없다.

건축물대장은 모든 건물에 있다. 표본에서 K-apt 에 없는 서초동아(12세대·7층)·광정(11세대·6층)도 대장으로 채워졌다. 이번 작업은 건축물대장을 받아 K-apt 가 없는 상세에 건물 정보를 보여 주고, 설명 문구·구조화 데이터에도 넣는 것이다.

성공 조건:
- K-apt 단지 정보가 없는 아파트·빌라·오피스텔 상세에서 건물 정보가 보인다. 틀린 건물 정보는 보이지 않는다.
- K-apt 가 연결된 상세와 대장이 연결되지 않은 상세는 지금과 똑같다.
- 상세 응답 속도가 눈에 띄게 느려지지 않는다.
- 수집이 운영 서버 메모리·DB 를 흔들지 않는다.

## 2. 목표 · 비목표 · 안티목표

목표
- 건축HUB 전국 대용량 파일(표제부·총괄표제부·전유공용면적) 정기 수집
- 실거래 상세 ↔ 대장 연결
- "건물 정보" 섹션 + 헤더 요약 줄 (K-apt 단지 정보가 없을 때만)
- 오피스텔은 상가 호실을 뺀 오피스텔 호수
- meta description · JSON-LD 반영

비목표 (이번에 하지 않음)
- 공동주택가격(공시가격) — 같은 건축HUB 에 파일(5.6GB)이 있지만 다음 단계
- 빌라·오피스텔 면적별 호수 막대 — 전유공용면적으로 만들 수 있으나 다음 단계 *(내 판단: 범위를 호수까지로 묶음)*
- K-apt 가 연결된 상세에 대장 값을 함께 표시
- 대장 건물명 표시·검색 별칭 (사용자 결정: 국토부 이름 유지)
- 지도·목록·지역 페이지·사이트맵 변경
- 건축HUB API 호출 수집 (일 1만 건 한도 — 파일로 대체)

안티목표 (돌아가도 실패로 본다)
- 같은 지번의 다른 단지·건물 값을 섞어 보여 주는 것. 애매하면 보여 주지 않는다.
- 오피스텔 호수에 상가·학원 호실을 더해 보여 주는 것
- 연결 안 된 상세에 빈 섹션·"정보 없음"
- 대장 조회 실패가 상세 전체 실패·noindex 로 번지는 것
- 수집이 운영 서버 메모리를 고갈시키는 것(파일 통째로 메모리 적재, 전국 호실 전체 집계)
- 운영 DB 에서 넓은 범위 집계·정렬을 새로 만드는 것 (2026-10 tmpdir 장애 교훈)

## 5. 수집

### 5.1 언제

- 별도 스크립트 `syncBuildingRegister` + 운영 cron 1줄, 매일 06:30 KST *(내 판단 — 03:00 부동산 수집과 겹치지 않는 시간)*.
- 시작하면 목록을 읽어 03/0303·0302 의 데이터제공년월을 저장된 값과 비교한다. 같으면 "변경 없음"으로 끝낸다(다운로드 0).
- 전유공용면적(0306)은 저장된 데이터제공년월보다 3개월 이상 새로울 때만, 또는 저장된 값이 없을 때 받는다.
- 부동산 쓰기 잠금(`sync-real-estate.sh` 의 잠금 디렉터리)이 잡혀 있으면 아무것도 하지 않고 끝낸다(다음 날 재시도).
- SyncHistory 에 기록한다(running → success/failed, 처리 행 수, 저장 행 수, 데이터제공년월, 최대 메모리).

### 5.2 메모리·디스크

- zip 은 디스크에 받는다(운영 여유 34GB). 처리 후 성공·실패와 관계없이 지운다.
- **스트리밍으로만 읽는다.** zip 엔트리를 조금씩 풀어 줄 단위로 처리하고, 줄은 처리 즉시 버린다. `adm-zip` 처럼 엔트리를 통째로 메모리에 올리는 방식은 금지. 운영 서버에 `unzip` 이 없으므로 서버 프로그램 설치 없이 Node 로 처리한다(파일 내 data descriptor 를 다룰 수 있는 방식 — 중앙 디렉터리 기반 스트리밍 라이브러리 또는 `zlib` 직접 사용; 새 의존성이면 Node 20 에서 lock 유지한 채 추가).
- 프로세스는 `--max-old-space-size=512` 로 실행한다. DB 쓰기는 500행 배치.
- 오피스텔 호수 집계는 **대상 지번만** 메모리에 둔다(§5.4).
- 첫 운영 실행 때 최대 RSS 를 SyncHistory/로그에 남기고 사용자에게 보고한다.

### 5.3 저장 (새 테이블 — 마이그레이션 필요)

이름은 빌더 재량, 아래는 역할.

1. **대장 표제부** — 저장 대상: 대장구분 2(집합) 행 전부 + 대장구분 1(일반) 중 주용도코드가 공동주택(`02000`)인 행. 아파트·연립·다세대·오피스텔이 모두 집합 대장이고, 일반 대장 공동주택은 예외 대비다.
   - 열: 관리PK(유일), 시군구, 법정동, 대지구분, 번, 지, 건물명, 동명, 대장종류, 주부속, 주용도코드·명, 기타용도, 세대수, 가구수, 호수, 지상층수, 지하층수, 승강기(승용+비상용), 주차 4종, 사용승인일, 구조명, 데이터제공년월, `raw`
   - 인덱스: (시군구, 법정동, 대지구분, 번, 지)
2. **대장 총괄표제부** — 전 행 저장(62만 행). 열: 관리PK, 지번 키 5개, 건물명, 주용도, 세대수, 가구수, 호수, 주건축물수, 총주차수, 사용승인일, 데이터제공년월, `raw`. 같은 인덱스.
3. **오피스텔 호수 집계** — (지번 키 5개, 건물명, 동명) 단위로 전유 호실 수를 용도별로: 오피스텔 호실 수, 전체 전유 호실 수, 데이터제공년월.
4. **법정동 이름 → 코드** — (시군구, 법정동코드, 동이름). 표제부의 대지위치에서 지번 앞 토큰으로 만든다("대구광역시 수성구 수성동4가 1125-14번지" → 수성동4가, 읍면+리면 "오송읍 서평리"처럼 두 토큰도 함께 기록). 행안부 API 를 따로 부르지 않아 대장과 같은 시군구 코드 체계가 된다 *(내 판단)*.
5. **원본 파일 기록** — 업무코드별 데이터제공년월·파일 ID·받은 시각·행 수 (K-apt `KaptSourceFile` 과 같은 역할).

교체 방식: 새 데이터제공년월로 전부 다시 쓴 뒤, 끝까지 성공했을 때만 이전 데이터제공년월 행을 지운다. 중간에 실패하면 이전 행이 남아 화면은 이전 달 기준으로 계속 나온다. 삭제는 인덱스 범위로 나눠서(넓은 단일 DELETE 금지).

### 5.4 오피스텔 호수 집계

1. 먼저 DB 의 표제부 테이블에서 "오피스텔 대상 지번" 집합을 읽는다: 주용도명 또는 기타용도에 `오피스텔` 이 들어간 행의 지번 키. 시군구 단위로 나눠 인덱스로 읽는다(전국 일괄 GROUP BY 금지). 수만 개 규모 예상 — 첫 실행에서 실제 개수 기록.
2. 전유공용면적 파일을 스트리밍하며 전유(구분 1) 행 중 지번 키가 집합에 있는 것만 본다.
3. (지번 키, 건물명, 동명) 별로 호실을 (동명, 호명) 으로 중복 없이 센다. 호실 용도가 오피스텔이면 오피스텔 호실 — 주용도명 = `오피스텔` 또는 기타용도에 `오피스텔` 포함. 한 호실에 전유 행이 여러 개면 하나라도 오피스텔이면 오피스텔 *(내 판단)*.
4. 검증 사례(API 로 확인): 아크로텔 강남역(서초동 1337-2) 전유 540호 = 오피스텔 471 + 소매점 67 + 학원 2 → 오피스텔 **471**. 대장 기타용도 "업무시설(오피스텔)-471호,근린생활시설-69호" 와 일치(대장 표기 69 는 소매점+학원).

표제부 기타용도에서 호수를 읽는 방식은 쓰지 않는다(표본 25곳 중 2곳만 숫자 기재).

## 6. 매칭 (상세 → 대장)

K-apt 단지 정보가 null 일 때만 실행한다. 오피스텔은 항상 K-apt 가 null 이므로 항상 실행.

### 6.1 지번 키 만들기

- 시군구 = 상세 `bjdCode`(5자리).
- 법정동코드 = §5.3-4 에서 (시군구, 동이름) 으로 찾는다. 상세 `dongName` 전체가 맞는 것을 먼저, 없으면 마지막 토큰. 0개거나 2개 이상이면 연결 안 함.
- 대지구분·번·지 = K-apt 매처의 `parseParcel` 재사용(산 → 1, 번·지 4자리 0 채움 비교).
- 주소 입력 순서는 K-apt 와 같다: `getBuildingInfo` 의 동·지번 1순위, 실패하면 상세 개요의 주소 후보(#956 합치기 결과)를 차례로 — 후보가 서로 다른 대장 결과를 가리키면 연결 안 함.

### 6.2 지번 안에서 고르기 (건물명 필터 — 사용자 결정)

지번의 표제부 주건축물(주부속 0) 행 중 주거 행만 남긴다:
- 아파트·빌라 상세: 세대수 > 0 이거나 주용도 공동주택인 행
- 오피스텔 상세: 오피스텔 호수 집계가 있는 (건물명, 동명) 이거나 주용도·기타용도에 오피스텔이 있는 행

그다음:
1. 남은 행의 정규화 건물명(`normalizeComplexName`, 빈 이름 제외)이 1종류 이하 → 모두 채택. 예: 야탑동 177 은 전부 "대원빌라3단지" → 국토부 이름 "목련마을자영빌라" 여도 채택.
2. 2종류 이상 → 상세 건물명과 `isNameMatch`(같음/포함 + 숫자열 같음)인 이름의 행만 채택. 맞는 이름이 정확히 1종류가 아니면 **연결 안 함**.
3. 빈 이름 행은 2번에서 버린다.

총괄표제부: 지번에 총괄이 정확히 1개이고 1번(이름 1종류)으로 채택됐을 때만 그 값을 쓴다. 그 외에는 표제부 합으로 계산한다.

### 6.3 유형 확인

- 아파트·빌라 상세인데 채택 행이 전부 오피스텔(세대수 0, 오피스텔 호수만) → 연결 안 함. 반대도 같다.
- 단, 빌라 상세에 대장 용도 오피스텔(주거용)이 섞인 사례(방배노블루체서리풀)가 있다. 빌라 상세에서 세대수 > 0 행이 있으면 그 행만 쓴다. 없으면 연결 안 함 *(내 판단 — 유형이 다른 값을 보여 주지 않는다)*.

## 7. 표시 값

채택 행 기준:

| 값 | 계산 |
|---|---|
| 세대수 (아파트·빌라) | 총괄 세대수, 없으면 표제부 세대수 합. 0 이면 표시 안 함 |
| 오피스텔 호수 | 채택 (건물명, 동명) 의 오피스텔 호실 합. 집계가 없으면(3개월 주기 사이 신축 등) 표시 안 함 — 표제부 호수로 대체하지 않는다 |
| 동수 | 채택 표제부 행 수(동명 기준 중복 제거). 1이면 "동수" 대신 생략 |
| 층수 | 지상층수 최댓값, 지하층수 최댓값 |
| 사용승인 | 채택 행 사용승인일 중 가장 이른 것(YYYYMMDD → "1994년 11월 (33년차)") |
| 주차 | 총괄 총주차수, 없으면 표제부 주차 4종 합. 0 이면 표시 안 함. 세대당(오피스텔은 호당) = 주차 ÷ 세대(호)수, 소수 둘째 |
| 승강기 | 승용+비상용 합. 0 은 "없음"으로 표시 |
| 용도 | 채택 행 주용도의 기타용도 대표값: 공동주택이면 기타용도(아파트/연립주택/다세대주택), 오피스텔이면 "오피스텔". 여럿이면 세대수 많은 순 2개 *(내 판단)* |
| 구조 | 채택 행에서 가장 많은 구조명 |

기준일 = 원본 파일 기록의 표제부 "(YYYY년 MM월)".

## 8. API

상세 개요 응답(`DetailOverview`)에 `buildingRegister: BuildingRegisterInfo | null` 을 추가한다. `complex` 가 있으면 항상 null(조회 자체를 하지 않음). 새 엔드포인트는 만들지 않는다.

```ts
interface BuildingRegisterInfo {
  kind: 'residential' | 'offitel';
  householdCount: number | null;   // residential
  offitelUnitCount: number | null; // offitel
  dongCount: number | null;
  topFloor: number | null;
  basementFloors: number | null;
  useApprovalDate: string | null;  // YYYY-MM-DD
  totalParking: number | null;
  elevatorCount: number | null;
  purposes: string[];              // ['연립주택'] / ['오피스텔']
  structure: string | null;
  sourceMonth: string | null;      // '2026-09'
  unitSourceMonth: string | null;  // 오피스텔 호수 기준 월(전유공용면적)
}
```

## 9. 화면

K-apt "단지 정보"와 같은 자리·같은 모양(C안)을 쓰되 출처와 항목만 다르다. `complex` 가 있으면 이 섹션은 없다.

- 섹션 제목: 동수 2 이상이면 "단지 정보", 1이면 "건물 정보" *(내 판단)*. 바로가기 메뉴 이름도 같게.
- 부제: "건축물대장 · 2026년 9월 기준"
- 표 (값 없는 줄 숨김):

| 줄 | 예 |
|---|---|
| 세대수 · 동수 | 216세대 · 9개 동 / 오피스텔 471호 |
| 층수 | 최고 4층 · 지하 1층 |
| 사용승인 | 1994년 11월 (33년차) |
| 주차 | 206면 · 세대당 0.95대 |
| 승강기 | 없음 / 3대 |
| 용도 · 구조 | 연립주택 · 철근콘크리트구조 |

- 헤더 요약 줄: K-apt 와 같은 형식 `216세대 · 9개 동 · 최고 4층 · 1994년 사용승인 · 단지 정보 ›` (오피스텔은 `오피스텔 471호 · 최고 20층 · 2016년 사용승인 · 건물 정보 ›`).
- 하단 출처: "출처: 국토교통부 건축물대장(건축HUB) · 세대수는 대장 기재 기준" — 오피스텔은 "오피스텔 호수는 호별 용도 기준(상가 제외), YYYY년 MM월 기준".
- SSR. 광고 슬롯 개수·위치는 바꾸지 않는다.

## 10. SEO

K-apt 와 같은 자리에 같은 규칙으로 넣는다.
- description 사실 절: 세대수(오피스텔은 "오피스텔 471호") → 전용면적 → 사용승인 연도. 사다리도 K-apt 와 같음.
- JSON-LD: `additionalProperty` 에 세대수(또는 오피스텔 호수)·동수·최고층·사용승인일·총주차대수. ApartmentComplex 이면 `numberOfAccommodationUnits` = 세대수.
- 화면 숫자와 같은 값이어야 한다.

## 11. 실패·경계 처리

- 대장 조회는 덧붙이는 정보: 실패하면 null, 상세 응답 코드·noindex 에 영향 없음(K-apt 와 같은 try/catch).
- 지번 파싱 실패(`가-240`, BL, 빈 값) → 연결 안 함(이름만으로 대장을 찾지 않는다).
- 시군구 코드 체계 차이(2026 전남광주 통합, 부천·화성 구 신설 등)로 법정동이 안 찾아지면 연결 안 함 — 운영 측정에서 시군구별 미연결이 몰리면 보고 후 별도 처리.
- 수집 실패는 기존 데이터를 지우지 않는다(§5.3 교체 방식). 상세는 이전 달 값으로 계속 나온다.
- 파일 열 수가 레이아웃과 다른 행은 건너뛰고 개수를 기록한다. 건너뛴 비율이 1% 를 넘으면 실패로 처리하고 교체하지 않는다 *(내 판단)*.

## 12. 검증

- 백엔드 단위: 줄 파서(열 수·빈 값·숫자), 대지위치 → 동이름(동·가·읍면+리), 저장 대상 필터, 오피스텔 호수 집계(아크로텔 강남역 축소 픽스처 → 471), 매칭(이름 1종류 채택·여러 종류 필터·못 가르면 불연결·유형 불일치 불연결·빌라 상세 오피스텔 혼재), 표시 값 계산, K-apt 있으면 조회 안 함.
- 수집: 작은 zip 픽스처로 스트리밍·교체·실패 시 이전 행 유지·변경 없음 스킵·3개월 주기 판정.
- 프런트: 섹션(제목 단지/건물, 오피스텔 호수 줄, 값 없는 줄 숨김, 승강기 없음), 헤더 요약, description, JSON-LD.
- 로컬 실데이터: 전국 파일로 로컬 수집 1회 → 서초동아(아파트, K-apt 없음), 야탑동 177(K-apt 있음 → 대장 섹션 없음), 아크로텔 강남역(471호), 탑마을(경향) 야탑동 510(이름 필터), 방배노블루체서리풀(빌라·오피스텔 혼재) 확인.
- 운영 측정(배포 후, 읽기 전용, 시군구 단위·동시 4 이하): 유형별 연결률(상세 수·거래량 비중), 첫 수집 시간·최대 RSS·저장 행 수, 상세 개요 응답 시간 변화.
