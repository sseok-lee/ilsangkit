# 청약 상세 광고② ↔ 광고③ 연속 노출 수정 (광고③ 재배치)

- **날짜**: 2026-07-03
- **대상 파일**: `frontend/pages/subscription/[id].vue` (단일 파일)
- **관련 페이지**: `/subscription/[id]` (청약 상세 — 분양·임대·임의공급 공통)
- **재현 사례**: https://ilsangkit.co.kr/subscription/5790 (시흥 은계 에피트(7차), 접수예정)

## 문제

청약 상세 페이지에서 광고 배너 2개(광고②·광고③)가 **콘텐츠 없이 연속으로** 붙어 렌더된다.

## 근본 원인 (라이브 HTML로 확인)

본문 광고 4개는 flex `order-N` **고정 위치**에 배치돼 있다. 광고② (`order-5`)와 광고③ (`order-7`) **사이의 유일한 콘텐츠는 "면적별 경쟁률 · 당첨 가점 분석" 블록(`order-6`)** 하나뿐이다.

이 경쟁률·가점 블록은 `v-if="competitions.length > 0"` / `v-if="validScores.length > 0"` 조건부이고, **당첨자 발표 전(접수예정·청약중)에는 데이터가 없어 통째로 숨겨진다.** 그 결과 광고②와 광고③가 인접 flex 아이템이 되어 사이 콘텐츠 없이 붙는다.

- 5790은 접수예정이라 경쟁률·가점·특별공급이 모두 비어 있고, 실제 렌더 블록은 `청약 일정 → 공급정보 → (광고②) → (광고③) → 위치·로드뷰 → 기본정보`로 광고②·③가 연속.
- 5790만의 문제가 아니라 **결과 미발표 청약(활성 상태 대부분)** 전반에서 발생.
- 광고①(헤더 뒤)·광고④(하단)는 앞뒤에 항상 콘텐츠가 있어 안전. **문제는 광고②↔광고③ 한 쌍뿐.**

## 결정

- **방향**: 위치 이동으로 해결. **광고 4개 개수는 유지**(수익 정책 — 사용자 결정).
- 광고 개수 축소·AdBanner 로직 변경은 하지 않는다.

## 설계

하단에서 데이터 상태와 무관하게 **항상 렌더되는 블록은 "기본정보"와 "관련 가이드" 둘뿐**이다(경쟁률·가점·특별공급·위치·로드뷰는 전부 조건부). 따라서 광고③를 **기본정보 뒤 · 관련 가이드 앞**으로 이동해 앞(기본정보)·뒤(관련 가이드) 모두 항상 콘텐츠가 보장되게 한다. → **어떤 청약 데이터 상태에서도 광고가 인접하지 않는다.**

### order 재배치 (전부 `order-N md:order-N` 동일)

| 블록 | 기존 order | 신규 order | 변경 |
|---|---|---|---|
| 헤더(MobileDetailHeader/PageHero) | 1 | 1 | — |
| 광고① | 2 | 2 | — |
| 청약 일정 | 3 | 3 | — |
| 면적별 공급정보 | 4 | 4 | — |
| 광고② | 5 | 5 | — |
| 면적별 경쟁률 / 당첨 가점 분석 | 6 | 6 | — |
| 면적별 특별공급 내역 / 신청현황 / 전월세 시세 | 8 | **7** | ↑ |
| 위치·로드뷰 (데스크톱/모바일/좌표없음 fallback) | 9 | **8** | ↑ |
| 기본정보 / 외부 링크 버튼 | 10 | **9** | ↑ |
| **광고③** | **7** | **10** | ⬇️ 이동 |
| 관련 가이드 | 11 | 11 | — |
| 광고④ / 데이터 정보 | 12 | 12 | — |

- 최종 order 범위는 1~12 유지(프로젝트 규칙 `order≤12` 준수).
- `<AdBanner class="order-7 ...">` 요소를 소스상으로도 **외부 링크 버튼 div 뒤 · 관련 가이드(RelatedGuides) 앞**으로 물리 이동(가독성 + DOM 소스 순서 정합). flex `order`가 시각 순서를 결정하므로 물리 위치 이동은 레이아웃에 필수는 아니나, 소스 혼선 방지를 위해 함께 이동.

### 결과 순서

- **얇은 페이지(5790 등)**: 헤더 → 광고① → 청약일정 → 공급정보 → 광고② → 위치·로드뷰 → 기본정보 → 광고③ → 관련가이드 → 광고④ → 데이터. (광고 자연 분산)
- **데이터 많은 페이지**: 광고② 뒤로 경쟁률·가점·특별공급·위치 여러 블록이 이어진 뒤 기본정보 → 광고③ → 관련가이드 → 광고④. (기존 광고②/③ 밀집보다 간격 개선)

## 스코프 밖 (변경하지 않음)

- 광고 개수(4개 유지), `AdBanner.vue` 로직, `useAdsPolicy`, SSR/hydration, SEO 메타·구조화데이터.
- 공매(`/auction`)·부동산(`/real-estate`) 상세의 유사 패턴 — 이번 건에서 다루지 않음(필요 시 별건).

## 검증 계획

1. `npm run lint` (frontend) 통과.
2. `npm run test` (frontend vitest) 통과 — 기존 `subscription/[id]` 관련 테스트 회귀 없음.
3. 렌더 순서 검증: dev 서버 또는 빌드 SSR HTML에서
   - (a) 접수예정/결과미발표 청약(예: 5790류): 광고 `<div class="ad-banner ...">` 2개가 인접하지 않음 확인.
   - (b) 결과발표 청약(경쟁률·가점 有): 광고 4개 모두 앞뒤 콘텐츠 보유, order 시각 순서 정상.
4. 데스크톱·모바일 두 뷰포트에서 order 시각 순서 동일 확인(위치·로드뷰 desktop/mobile 분기 포함).
