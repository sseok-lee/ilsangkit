# 모바일 상세페이지 구조 재설계 (시설 · 부동산)

- **작성일**: 2026-06-10
- **범위**: 모바일 뷰포트(`< md`, 768px 미만)에 한정. 데스크톱(`md:` 이상) 레이아웃은 변경하지 않는다.
- **대상 페이지**:
  - 시설 상세: `frontend/pages/[category]/[id].vue`
  - 부동산 상세: `frontend/pages/real-estate/[realEstateType]/[city]/[district]/[buildingName].vue`

---

## 1. 배경 / 문제

현재 두 상세페이지의 모바일 구조는 데스크톱 레이아웃을 단순히 1컬럼으로 좁힌 형태에 가깝다. 핵심 문제는 **맨 위 240px 라이브 지도**다.

- 카카오맵 SDK가 무거워 **LCP/렌더를 잡아먹는다**(Core Web Vitals 불리).
- 지도가 첫 화면을 차지하면서, 사용자가 가장 먼저 알아야 할 정보(시설: 영업상태·거리·운영시간 / 부동산: 시세·전월대비)가 **폴드 아래로 밀린다.** CLAUDE.md 설계 원칙 "0.5초 안에 원하는 정보 위치 파악"과 충돌.
- 상세페이지에 도착한 사용자는 이미 대상을 선택한 상태다. 여기서 지도의 역할은 "발견"이 아니라 **"방향 안내 + 위치 감각"** 으로 약하다. 프라임 영역을 차지할 이유가 적다.
- 부수적으로 부동산 페이지의 `전·월세 거래 비중` 섹션이 위치/주변 섹션 사이에 끼어 있어 맥락이 어색하다.

## 2. 설계 방향 (확정안: "핵심정보 우선, 지도는 중간")

대안 3가지(세그먼트 탭형 / 요약+아코디언 / 미니내비 스크롤형)와 지도 배치 3가지(정적 썸네일 / 핵심정보 우선·지도 중간 / 현행 유지)를 비교한 끝에 **"핵심정보 우선 + 지도를 중간 위치 섹션으로 강등"** 안을 채택했다.

핵심 원칙:

1. **핵심 정보를 폴드 위로.** 페이지 최상단에 이름/상태/핵심 지표 + 액션을 배치한다.
2. **지도 강등(위치 이동).** 맨 위 라이브 지도를 없애고, **기존 라이브 지도/로드뷰를 그대로** 중간 `위치·로드뷰` 섹션으로 옮긴다. 표현 방식은 현행 유지(라이브 `FacilityMap` + `FacilityRoadview`). 지도가 폴드 아래로 내려가므로 LCP 부담은 사실상 해소된다.
3. **기존 정보 섹션의 내부는 손대지 않는다.** 섹션의 순서·위치만 재배치한다.

## 3. 변경하지 않는 것 (중요)

- **데스크톱 레이아웃**: 사이드바(라이브 지도 + 버튼 + 쿠팡), 인라인 광고, PageHero 등 `md:` 이상 표현은 현행 유지.
- **각 정보 섹션의 내부 구조/내용**:
  - 시설: `DetailBasicInfo`, `DetailFacilityStatus`, `FacilityRoadview`, `DetailNearby`, 유튜브/블로그, `DetailContextLinks`
  - 부동산: 시세추이(`TransactionModeTab`/`RentTypeToggle`/`AreaSelector`/요약카드/`PriceTrendChart`), `TransactionTable`, `RentRatioBar`, `NearbyComplexCard`, 주변 생활시설
  - 위 컴포넌트들은 그대로 재사용하며 내부를 바꾸지 않는다.
- **광고 개수**: 총 개수는 유지하고 위치만 조정한다(아래 4절). 광고 정책은 사용자 결정 사항.

## 4. 변경 사항 (모바일)

### 4-1. 공통

| # | 변경 | 설명 |
|---|------|------|
| C1 | 맨 위 라이브 지도 제거 | 현재 `md:hidden` 상단 240px `FacilityMap` 블록 삭제 |
| C2 | 핵심 정보 헤더 신설 | 최상단에 **제목 + 상태칩 + 정보칩 + 액션 pill** 블록(아래 4-4) |
| C3 | 지도/로드뷰 위치 이동 | 맨 위 지도 블록 제거 후, **기존 라이브 `FacilityMap` + `FacilityRoadview`를 그대로** 중간 `위치·로드뷰` 섹션에 배치. 표현 변경 없음. 기존 "지도 크게 보기" → 풀스크린 오버레이(`isMapExpanded`) 동작 유지. 뷰포트 진입 시 지연 마운트(IntersectionObserver) 권장 |
| C4 | 하단 고정 바 제거 | `md:hidden fixed bottom-0` sticky CTA(공유/길찾기) 및 하단 `h-24` 스페이서 삭제. 공유·길찾기는 핵심 정보 헤더 pill로 대체 |

```
헤더(AppHeader, 기존)
브레드크럼
핵심 정보 헤더  ← C2 신설 (단지명 + 상승/하락 칩 + 정보칩 + 시세요약 카드 2칸 + 공유/길찾기 pill)
[광고 rectangle 280]   ← 신규 추가

전·월세 거래 비중 (RentRatioBar)  ← (이동) 위치 옆 → 거래내역 바로 아래(가격 묶음). 전월세 탭일 때만 표시
```

부동산 변경 요약:
- **광고 신규 1개**: 핵심 정보 헤더 바로 아래.
- **전·월세 거래 비중 이동**: 위치 섹션 옆 → 거래내역 바로 아래(시세·거래 가격 묶음에 인접).
- 부동산은 입지보다 **시세**가 판단 핵심이므로 시세추이·거래내역을 위치보다 위에 둔다.

### 4-4. 핵심 정보 헤더 (신규 UI)

현재 `PageHero`(eyebrow 배지 + 제목 + 설명 + stats 그리드)를 모바일에서 다음 형태로 재구성한다. **데이터·액션 모두 기존에 존재하는 것**이며 신규 기능은 없다.

**시설**
- 제목(h1) + 영업상태 칩(`OperatingStatusBadge` 재사용 가능)
- 정보칩: 거리 · 운영 종료시각 · 평점 · 후기 수 · (카테고리별 특성, 예: 심야운영)
- 액션 pill 4개: `전화` · `주소복사` · `공유` · `길찾기`(primary)
  - 전화/주소복사: 현재 `DetailBasicInfo` 내부 동작을 끌어올림
  - 공유/길찾기: 현재 sticky 하단 바 동작을 끌어올림(길찾기는 카카오맵/네이버맵 선택 드롭다운 유지)

**부동산**
- 제목(h1, 단지명) + 시세 추세 칩(▲상승/▼하락/유지)
- 정보칩: 부동산 타입 · 지역 · 전용면적 · 세대수 등
- 시세 요약 카드 2칸: 최근 평균(매매) · 전월 대비
- 액션 pill 2개: `공유` · `길찾기`(primary)  ※ 시세알림 없음

### 4-5. 위치·로드뷰 섹션 (C3 구현 방향)

- 기존 라이브 `FacilityMap` + `FacilityRoadview`를 **표현 변경 없이** 중간 위치 섹션으로 옮긴다. 정적 썸네일은 사용하지 않는다.
- 지도가 폴드 아래로 내려가 더 이상 LCP 후보가 아니므로, 라이브 지도를 그대로 써도 초기 성능 부담이 작다.
- 추가 안전장치로 **IntersectionObserver 지연 마운트**를 권장: 위치 섹션이 뷰포트 근처에 올 때 지도를 초기화해 첫 렌더 비용과 불필요한 SDK 호출을 줄인다(필수는 아님, 여력 시 적용).
- 기존 "지도 크게 보기" → 풀스크린 오버레이(`isMapExpanded`) 동작은 그대로 유지한다.
- `FacilityRoadview`는 이미 탭 시 재생 방식이므로 그대로 둔다.

## 5. 구현 시 고려 (아키텍처)

**모바일/데스크톱 분기 전략** — 본 변경은 모바일만 대상이고 데스크톱은 픽셀 동일하게 유지해야 한다. 두 뷰의 섹션 순서가 달라지므로:

- 권장: 페이지 템플릿에서 **모바일 배열(`md:hidden`)과 데스크톱 배열(`hidden md:block`/사이드바)을 분리**하되, 내부 섹션 컴포넌트(`DetailBasicInfo` 등)는 양쪽이 동일하게 재사용한다. 컴포넌트 재사용이므로 로직 중복은 없고 "배치"만 두 벌이 된다.
- 핵심 정보 헤더는 모바일 전용 컴포넌트로 신설(예: `MobileDetailHeader.vue` / `MobileRealEstateHeader.vue`). 데스크톱은 기존 `PageHero` 유지.
- 위치·로드뷰 섹션은 모바일 배열에서 기존 `FacilityMap`/`FacilityRoadview`를 재사용(신규 지도 컴포넌트 없음). 데스크톱 사이드바 라이브 지도는 유지.
- 이 분기로 인한 마크업 중복은 감수한다(데스크톱 안전성 우선). 향후 데스크톱도 같은 방향으로 통합할지는 별도 결정.

**SSR 주의** — 라이브 지도/로드뷰/오버레이는 기존대로 클라이언트 가드(`import.meta.client`) 유지.

## 6. 영향 받는 파일 (예상)

- `frontend/pages/[category]/[id].vue` — 모바일 섹션 재배열, 상단 지도 제거, 하단 바 제거, 핵심 정보 헤더 삽입, 지도/로드뷰를 위치 섹션으로 이동
- `frontend/pages/real-estate/[realEstateType]/[city]/[district]/[buildingName].vue` — 동일 + 전월세 비중 이동, 광고 추가
- 신규: 모바일 핵심 정보 헤더 컴포넌트(시설/부동산). 지도 관련 신규 컴포넌트 없음(기존 재사용)
- 재사용(수정 없음): `components/facility/detail/*`, `components/realEstate/*`, `FacilityMap.vue`, `FacilityRoadview.vue`, `AdBanner.vue`, `OperatingStatusBadge.vue`, `navigation/Breadcrumb.vue`
- 관련 컴포저블(수정 가능성): `useFacilityDetail.ts`, `useRealEstate.ts`, `useKakaoMap.ts`

## 7. 검증 / 완료 기준

- 모바일(`< md`)에서 두 페이지의 첫 화면에 핵심 정보(시설: 이름·상태·거리·시간 / 부동산: 단지명·시세·전월대비)가 지도보다 먼저 보인다.
- 데스크톱(`md:` 이상) 레이아웃이 변경 전과 시각적으로 동일하다(회귀 없음).
- 위치 섹션의 라이브 지도/로드뷰가 정상 동작하고, "지도 크게 보기" → 풀스크린 오버레이가 기존대로 동작한다.
- 공유/길찾기/전화/주소복사 액션이 헤더 pill에서 모두 동작한다.
- 광고 개수: 시설/부동산 각 변경 후 의도한 위치·개수와 일치.
- 기존 vitest 통과(`frontend`), 상세 컴포넌트 테스트 갱신 필요 시 함께 수정.
- 모바일 LCP가 라이브 지도 제거로 개선(체감/측정).

- 신규 기능(시세알림 등) 추가
