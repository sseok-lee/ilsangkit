## 1. 왜 하는가

관리비는 매수·임차를 고민하는 사람이 실거래가 다음으로 궁금해하는 숫자이고, 단지마다 값이 달라 상세 페이지를 서로 구별시키는 고유 정보다. 단지 정보(세대수·층수 등)에 이어 같은 K-apt 데이터로 붙일 수 있다.

성공 조건:
- 단지 정보가 붙은 상세에서 관리비(세대 평균·구성·계절·같은 구 비교·항목 상세)가 보인다.
- 숫자가 어떻게 계산됐는지(세대 평균, 기준 월, 출처)가 화면에 분명하다.
- 이상한 값(0원, 수천만 원)은 보이지 않는다.
- 연결 안 된 상세와 관리비 데이터가 없는 단지는 지금과 같다.

- 상세 "관리비" 섹션(B안): 세대 평균 월 관리비, 구성, 여름·겨울·연평균, 최근 12개월 월별 막대, 같은 시군구 대비 ㎡당 공용관리비, 항목별 상세(펼침), 관리사무소 연락처

### 3.2 수집

- 기존 K-apt 수집(`syncKapt`, 03:00 수집 끝단)에 관리비를 더한다. 매 실행마다:
  - 올해 주간 파일: 기준일이 저장된 것보다 새로우면 받는다(#961 과 같은 규칙).
  - 전년도 파일: 파일명(날짜 접두)이 저장된 것과 다르면 받는다. 1월에 해가 바뀌면 "전년도"가 바뀐다.
- 단지코드+발생년월 기준 upsert. 받은 파일에 없는 기존 행은 지우지 않는다 *(내 판단 — 연도 파일과 주간 파일이 서로의 달을 덮지 않으므로, 지우기 규칙이 오히려 위험)*.
- 52개 항목을 전부 저장한다(데이터 수집 최대화 원칙). 저장 형태(컬럼/JSON)는 빌더 재량이되, 화면이 쓰는 값(공용·개별·장충·항목 상세)은 조회가 가볍게.
- 파일 크기가 커서 스트리밍 파서로 읽는다. 첫 수집은 약 44만 행.
- 최소 행 수 가드(파일이 잘려 오면 멈춤), 헤더 검증(필수 헤더가 없으면 멈춤)은 #961 과 같은 방식.
- 수집 단계 시간 예산을 늘린다(현재 kapt 15분). 빌더가 로컬 실측 후 정한다.

### 3.3 미리 계산하는 값

페이지 요청 때 넓은 집계를 하지 않도록 수집 끝에 계산해 둔다.

- **기준 월**: 전국에서 관리비가 올라온 단지 수가 가장 많은 달의 95% 이상인 가장 최근 달 *(내 판단)*. 지금은 2026-08.
- **같은 시군구 ㎡당 공용관리비 중간값**(기준 월): 시군구(필지의 `sggCode`)별, 정상값만, 5단지 이상일 때만. 5단지 미만이면 비교 줄을 숨긴다 *(내 판단)*.
- 계산 결과는 작은 테이블 하나에 둔다(시군구·월·중간값·단지 수).

## 4. 화면 계산 규칙

모든 금액은 **세대 평균** = 단지 월 부과액 ÷ 세대수.

| 항목 | 계산 |
|---|---|
| 큰 숫자 | 기준 월의 (공용관리비 + 개별사용료 + 장충금 월부과액) ÷ 세대수. 이 단지에 기준 월이 없으면 그보다 이전 최근 월(최대 2개월 전까지). 그것도 없으면 섹션 숨김 |
| 구성 | 같은 달의 공용·개별·장충 각각 ÷ 세대수, 막대는 비율 |
| 여름 | 가장 최근 7·8월(둘 다 있어야) 평균 |
| 겨울 | 가장 최근 12·1·2월(셋 다 있어야) 평균 |
| 연평균 | 기준 월로 끝나는 최근 12개월 평균, 10개월 이상 있을 때만 |
| 월별 막대 | 기준 월로 끝나는 최근 12개월. 기준 월 뒤에 일부 단지만 올라온 달이 이 단지에 있으면 흐리게 덧붙인다 *(내 판단)* |
| ㎡당 공용관리비 | 기준 월 공용관리비 ÷ 관리비부과면적, 같은 시군구 중간값과 막대 비교. 이 단지에 기준 월 값이 없으면(큰 숫자가 이전 달로 대체된 경우) 비교 줄은 숨긴다 — 다른 달끼리 비교하지 않는다 |
| 항목 상세 (펼침) | 기준 월의 세부 항목을 세대 평균으로: 일반관리비·청소비·경비비·소독비·승강기유지비·수선유지비·위탁관리수수료 / 난방·급탕·가스·전기·수도(공용+전용)·기타 / 장충금 적립률 등. 0 인 항목은 숨김 |
| 관리사무소 | 연락처(전화 링크)·주소. 없으면 숨김 |

예 (개포래미안포레스트 2,296세대, 실제 값):
- 8월 세대 평균 44만 4,578원 = 공용 17만 3,395원 + 개별 25만 2,105원 + 장충금 1만 9,078원
- 여름(26.7~8) 43만 5,664원, 겨울(25.12~26.2) 47만 3,096원, 연평균(25.9~26.8) 41만 4,348원
- ㎡당 공용관리비 1,626원, 강남구 178단지 중간 1,527원

### 4.1 이상값

- 세대수가 없거나 0 이면 세대 평균 전부 숨김. 관리비부과면적이 없으면 ㎡당 비교만 숨김.
- 기준 월 세대 평균이 **1만 원 미만 또는 200만 원 초과**면 섹션 숨김 *(내 판단 — 2026-08 전국 20,079단지 중 1만 원 미만 5곳, 200만 원 초과 38곳. 0원, 수천만 원 같은 원본 오류)*. 월별 막대·계절 계산에서도 같은 범위를 벗어난 달은 뺀다.
- 시군구 중간값 계산에서도 같은 범위 밖 단지는 뺀다.

## 6. API · 성능

- 단지 정보와 같은 방식으로 상세 개요 응답의 `complex` 안(또는 옆)에 관리비를 붙인다. 별도 요청을 만들지 않는다 *(내 판단 — 단지 정보 결정과 같은 이유: 이미 SSR 로 불리는 응답)*.
- 조회는 단지코드로 최근 약 15개월 행 + 시군구 중간값 1행. 인덱스 조회만.
- 목표: 관리비로 늘어나는 개요 응답 시간 20ms 이하.
- 관리비 조회 실패는 관리비만 숨기고 개요·단지 정보는 그대로.

## 9. 구현 결정 (2026-10-29, 빌더)

- **테이블**: `KaptMaintenanceFee` 단지코드+발생년월(CHAR 6) 유니크, 금액 44개 BIGINT + 장충금 적립률 DOUBLE. 시도·시군구·읍면·동리·단지명 5개 헤더는 `KaptComplex` 와 같아 저장하지 않는다. 적립률은 원본에 27억 같은 오류값이 있어(2026 파일 53건) DOUBLE, 화면에는 쓰지 않는다(단위 불명).
- **시군구 중간값**: `KaptFeeSggMedian`(시군구·월·㎡당 중간값·단지 수), 전국은 `sggCode '00000'` — 상세는 이 행의 월을 기준 월로 읽는다. 단지의 시군구 = 그 단지 필지 sggCode 중 가장 작은 값.
- **기준 월 비율 95% → 90%**: 실데이터 단지 수 최대 21,546(2026-06) 대비 8월 20,083(93%), 9월 11,370(53%). 95% 면 7월이 되어 예시(8월 부과분)와 어긋난다.
- **전년도 파일**: 주간 기준일이 바뀐 실행에서만 받고, 파일명이 저장된 것과 같으면 반영하지 않는다(69MB 매일 다운로드 회피).
- **행 수 하한**: 올해 파일 = 15,000 × (기준일 월 − 2), 1~2월은 0. 전년도 파일 = 200,000. 스트리밍이라 하한은 다 읽은 뒤 확인하고, 걸리면 출처를 기록하지 않아 다음 실행이 다시 받는다.
- **수집 예산**: kapt 단계 15분 → 30분. 로컬 전체 새로 받기 178초·최대 메모리 1.3GB, 관리비 437,079행.
- **응답 시간**: 관리비 조회 추가분 중간값 5~9ms(로컬).
- **화면**: 시군구 이름은 응답에 없어 "같은 시군구 중간(N단지)"로 쓴다. 관리사무소 번호는 숫자만 오면 하이픈을 넣는다.
