# 홈 "오늘의 부동산 시장" 개편 — 설계

- 작성일: 2026-07-20
- 상태: 승인됨 (구현 대기)
- 범위: 홈 부동산 섹션 재구성 (현 `HomeHotspotSignals` 자리) + "이번 주 인기 단지" 제거
- 목적: **홈 방문자의 부동산 경험 개선** (검색 유입 견인이 아님 — "전제" 참조)

## 요약

현 홈의 부동산 섹션은 "변동률·랭킹"(뜨는 동네, 인기 단지) 중심이라 투자자 관점에
가깝다. 첫 방문자가 실제로 궁금해하는 **절대 시세**("우리 동네가 지금 얼마?")를
맨 위로 올리고, 변동률은 보조로 강등, "인기 단지"는 제거한다. 거래 적은
지역·유형은 표본 적응으로 견딘다.

세 블록으로 재구성:
- **A · 우리 동네 시세** (신규, 메인) — 첫 방문은 **전국 뷰**(시·도별 시세 비교)로
  시작, 지역을 고르면 **우리 동네 뷰**로 전환·기억
- **B · 전국 거래 활발도** (신규, 한 줄)
- **C · 뜨는 동네** (기존 `HomeHotspotSignals` 재사용, 강등 배치)

## 전제 (정직하게 기록)

- **이 개편은 방문자 경험 개선이 목적이다. 검색 유입 견인은 목표가 아니다.**
  GSC 실측(2026-06-22~07-20): "실거래"·"시세" 검색 유입 **0건**. 표시된 유입 검색어는
  전부 생활시설(어린이집·주차장·쓰레기 배출·병원). 홈(`/`) 자체는 clicks 22 /
  impressions 40으로 유입 대부분이 직접·브랜드 방문. 즉 **부동산 시세 검색으로 사람이
  들어오지 않는다.** 이 개편이 그 유입을 늘린다는 보장은 없다.
- 부동산 SEO 유입 자체는 별개의 큰 과제(색인·노출 문제, 기존 진단 다수). 이 스펙 범위
  밖이다.
- 따라서 성공 지표는 "유입 증가"가 아니라 **홈 부동산 섹션의 이해도·클릭률**(방문자가
  시세를 보고 상세로 넘어가는지)이다.

## 데이터 실측 근거 (프로덕션, 2026-06~07)

- `dealAmount`/`deposit`는 **만원 단위**. 표시 계층에서 억 단위 포맷팅(제약 없음).
- 강남구 아파트 매매(2026-06): 평당 11,458만원, 평균 30.6억, 193건. 평형별 59㎡
  16.4억 / 84㎡ 27.9억 / 114㎡ 39.3억. 전세 84㎡ 9.9억.
- **신고 시차 약 2일** (오늘 07-20 기준 최신 거래일 07-18). "최근 N일" 윈도우가 빈
  결과가 되지 않는다.
- 시·군·구 단위 표본 분포(아파트 2026-06): 274개 중 **30건 이상 196개(72%)**, 10건
  미만 44개(16%).
- **빌라는 절반이 시·군·구 월 10건 미만**(262개 중 133개). 오피스텔은 더 심함. →
  표본 적응이 이 조합에서 자주 작동.

## 아키텍처

```
홈 SSR → GET /api/real-estate/local-market?citySlug=&districtSlug=&type=&txn=
       → localMarketService (표본 적응 집계 + 억 단위 직렬화)
       → MySQL (city/district/dealYear/dealMonth 인덱스; 날짜필터 sargable)
```

- 기존 `getHomeDashboard`는 hotspot(C) + B용 거래량을 계속 제공. A는 SSR 첫 렌더 시
  지역 없이 호출(전국 뷰), 사용자가 지역을 고르면 클라이언트가 재호출(우리 동네 뷰).
- 신규: `localMarketService.ts` + 라우트 1개.
- 제거: `getTrendingBuildings`(홈 전용, 타 사용처 없음 확인) + `HomeTrendingBuildings.vue`.

## A · 우리 동네 시세 (`HomeLocalMarket.vue`)

두 모드를 가진다. 저장된 지역 유무로 자동 결정된다.

### 모드 1 — 전국 뷰 (첫 방문, `localStorage` 비어있음)

특정 동네를 강요하지 않고 **시·도별 시세 비교**를 먼저 보여준다.

- **시·도별 평당 시세 막대 비교** — 평당가 내림차순(실측: 서울 5,251만원 → 경기
  2,640 → … → 전남 896). 각 행 = 시·도명 + 막대(평당가 비례) + 평당가 + 거래량.
- **행 클릭 → 그 시·도로 드릴다운**(시·군·구 선택으로 이어짐).
- **"우리 동네 시세 보기" CTA** — 내 위치 / 지역 선택 유도.
- 표본 적응 불필요(시·도는 항상 표본 충분; 제주도 시도 전체 157건).

### 모드 2 — 우리 동네 뷰 (지역 선택/내 위치 후)

- **지역 선택(하이브리드):** 전국 뷰에서 시·도 → 시·군·구 2단계 선택, 또는 "내 위치"
  버튼(옵션, 권한 거부·SSR 시 전국 뷰 유지) → 선택을 `localStorage`에 기억해 재방문
  시 이 모드로 복원(저장값이 현행 지역 slug와 불일치하면 전국 뷰로 폴백). "전국으로"
  버튼으로 모드 1 복귀 가능.
- **탭:** 유형(아파트/빌라/오피스텔) × 거래타입(매매/전세/월세). (전국 뷰에도 동일 탭)
- **본문:** 평당 시세(억 단위) + 전월 대비 + 평형별 평균 + 최근 실거래 리스트.
- 표본 적응(아래 계단) 적용.

### 표본 적응 (계단) — 모드 2(우리 동네 뷰)에만 적용

`localMarketService`가 아래 순서로 시도해 **첫 번째로 표본이 충분한 결과**를 반환하고,
어느 단계로 해결됐는지 `fallback` 필드로 알린다. (모드 1 전국 뷰는 시·도 집계라
표본 적응이 필요 없다.)

| 단계 | 조건 | 동작 |
|---|---|---|
| 1 | 시·군·구 + 최근 1개월, 표본 ≥ `MIN_SAMPLE` | 그대로 표시 (`fallback: none`) |
| 2 | 1 부족 → 시·군·구 + 최근 3개월(분기) | 기간 확대 (`fallback: quarter`) |
| 3 | 2 부족 → 시·도 + 최근 1개월 | 지역 확대, "OO도 기준" 안내 (`fallback: city`) |
| 4 | 3 부족(표본 0) | 시세 숫자 생략, 최근 실거래만 (`fallback: dealsOnly`) |

- `MIN_SAMPLE = 20` (평당가·평균가 대표성 기준. 실측상 아파트 시군구 72%가 30건+이라
  1단계로 대부분 해결; 빌라·오피스텔은 3단계로 자주 폴백).
- **평형별**: 각 평형 버킷(59㎡이하/84㎡대/114㎡대/대형)은 **버킷당 ≥ 5건일 때만**
  표시(적으면 그 버킷 숨김). 표본 튐 방지.
- **최근 실거래**: 표본 무관하게 있으면 최대 5건 표시(단지명·전용면적·층·거래일·금액).

### "기간"의 정의
- 1개월 = 데이터 최신일 anchor 기준 최근 30일(신고 시차 대응, NOW 기준 아님).
- 분기 = anchor 기준 최근 90일.
- anchor(최신 거래일)는 `MAX(dealDate)`가 아니라 인덱스 친화 조회
  (직전 PR의 hotspot anchor와 동일 패턴; 성능은 그 PR의 follow-up과 함께 개선).

## B · 전국 거래 활발도 (`HomeMarketPulse.vue`)

한 줄: "이번 주 전국 아파트 **N건** · 전주 대비 **▲X%**".

- "이번 주" = 데이터 최신일 anchor 기준 최근 7일. "전주" = 직전 7일.

  데이터로 정확·안정.
- `getHomeDashboard` 응답에 포함(SSR 1회). 캐시는 대시보드 캐시에 편승.

## 엔드포인트 응답 형태

`citySlug`/`districtSlug` 유무로 모드가 갈린다.

**모드 1 — 전국 뷰** (지역 파라미터 없음):
```
GET /api/real-estate/local-market?type=apt&txn=sale

{
  "mode": "nationwide",
  "byCity": [ { "cityName": "서울", "citySlug": "seoul",
               "pyeongPriceManwon": 5251, "txnCount": 4825 }, ... ]  // 평당가 내림차순
}
```

**모드 2 — 우리 동네 뷰** (지역 파라미터 있음):
```
GET /api/real-estate/local-market?citySlug=seoul&districtSlug=gangnam&type=apt&txn=sale

{
  "mode": "local",
  "resolved": { "level": "district", "regionLabel": "서울 강남구",
                "periodMonths": 1, "sampleCount": 193 },
  "fallback": "none",                        // none | quarter | city | dealsOnly
  "headline": { "pyeongPriceManwon": 11458, "avgPriceManwon": 305617,
                "deltaPct": 0.6, "txnCount": 193 } | null,   // dealsOnly면 null
  "byArea": [ { "band": "84㎡대", "avgPriceManwon": 279000, "count": 59 }, ... ],
  "recentDeals": [ { "buildingName": "신현대11차", "area": 183.4, "floor": 9,
                     "priceManwon": 1050000, "dealDate": "2026-07-13" }, ... ]
}
```

- SSR 첫 렌더는 지역 파라미터 없이 호출 → 전국 뷰. 사용자가 지역을 고르면 클라이언트가
  파라미터를 붙여 재호출 → 우리 동네 뷰.
- 금액은 **만원 단위 정수**로 반환, 억/만원 포맷은 프론트.
- BigInt/Decimal은 기존 `serializeRow` 패턴으로 Number 직렬화.
- `asyncHandler` + Zod `validate` (쿼리) 기존 라우트 패턴 준수.

## 성능 · 캐싱

- 지역별 집계는 `(city,district,dealYear,dealMonth)` 인덱스 range로 sargable(직전 PR).
- **캐시 필수**: (citySlug, districtSlug, type, txn) 키로 인메모리 캐시, TTL 1시간
  (홈 대시보드와 동일). 조합이 많으므로 LRU 상한(예 500개)으로 메모리 bound. 전국
  뷰(모드 1)는 (type, txn) 9개 조합뿐이라 확실히 캐시됨 — SSR 첫 화면이라 특히 중요.
- 응답에 `Cache-Control: s-maxage=3600`으로 nginx/CDN 캐시 편승.
- 표본 적응은 단계당 1쿼리(최대 3~4). 캐시 미스 시에만 발생.

## 테스트

- `localMarketService` 단위: 전국 뷰(모드 1) 시·도별 집계·평당가 내림차순 정렬;
  우리 동네 뷰(모드 2) 표본 적응 계단(1→2→3→4 각 분기), `MIN_SAMPLE` 경계, 평형 버킷
  5건 임계, dealsOnly 폴백. Prisma 모킹(기존 서비스 테스트 패턴).
- 억/만원 포맷 유틸 단위(경계: 1억 미만, 억+만원 혼합, 0).
- 지역 선택 composable: 기본값·localStorage 복원·잘못된 저장값 방어.
- `HomeLocalMarket.vue`: 모드 1(전국 뷰 시·도 막대) / 모드 2 폴백별 렌더(정상/기간확대
  배지/시도폴백 안내/실거래만) / 모드 전환(전국↔우리동네)·localStorage 복원.
- 제거 회귀: `HomeTrendingBuildings` 제거 후 홈 렌더·대시보드 응답 타입 정합.
- 프론트 전체 vitest + 백엔드 vitest 통과.
