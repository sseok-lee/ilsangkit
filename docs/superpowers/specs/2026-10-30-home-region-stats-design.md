# 홈 지역 시세 통계 설계 ("우리 동네 거래" 보강 + "요즘 거래가 늘어난 지역")

- 작성: 2026-10-30
- 시안: https://claude.ai/artifact/SYFVfdkV4kCjSPt9PNKUnt (③ 홈, ③ 모바일 — 수치는 예시)
- 배경: 집품 비교 작업 4번 "지역 랭킹·통계"의 첫 단계. 구 허브(①)·시도 비교(②)는 이번 범위가 아니다.

## 1. 의도

홈은 지금 거래 **건수**만 보여주고, "인기 지역"은 시·도 이름 칩을 고정으로 늘어놓을 뿐이다.
지역의 시세 수준(평당가)과 요즘 움직임(거래가 늘어난 곳)을 홈에서 바로 보여줘서
처음 온 사람도 "이 동네가 어느 정도 가격이고 요즘 어떤지"를 한눈에 알게 한다.
"늘어난 지역" 목록은 매일 바뀌는 내부 링크라 구 단위 부동산 허브가 더 자주 크롤된다.

## 2. 목표 · 비목표 · 반목표

목표
- "지금, 우리 동네 거래는" 섹션에 선택 지역의 **아파트 매매 평당가 중간값·전년 대비·최고가 거래 TOP 3** 줄을 더한다.
- 그 바로 아래에 **"요즘 거래가 늘어난 지역"** 섹션을 새로 두고, 기존 "인기 지역" 칩 섹션을 지운다.
- 숫자는 매일 03:00 수집 때 미리 계산해 둔 요약 테이블에서만 읽는다.

비목표
- 구 허브 시세 동향 섹션, 시·도 구별 비교 표 (다음 단계).
- 빌라·오피스텔 평당가 (아파트 매매만).
- "이번 주 신고가" (대표 시세 2단계 이후).

반목표 (이러면 실패)
- 홈 요청마다 운영 DB에서 거래 테이블을 집계한다 (tmpdir 장애·풀 고갈 전례).
- 신고 지연 때문에 "거의 모든 지역 감소"처럼 보이는 순위.
- 거래 몇 건짜리 지역이 "+200%"로 1위에 오르는 순위.
- 직거래·취소 거래가 최고가 TOP 3에 오른다.

## 3. 사용자가 정한 것

- 홈만 작업한다 (10/30).
- 배치 A안: 우리 동네 거래 → **요즘 거래가 늘어난 지역** → 광고 → 청약·임대 일정 … 광고는 한 섹션 아래로 내려간다. "인기 지역" 칩 섹션은 삭제.
- "늘어난 지역" 비교 기준 A안: **신고가 끝난 구간끼리** — 계약일 기준 31~60일 전 vs 61~90일 전.
- 거래 20건 미만 지역 제외, 범위 탭 전국·수도권·지방 (시안대로).

## 4. 접근 방식 (검토한 것)

| 방식 | 장점 | 단점 |
|---|---|---|
| A. 기존 `home-market` API에서 매 요청 집계 + 메모리 캐시 | 테이블 추가 없음 | 12개월 중간값·전국 시군구 순위는 무거움, 콜드 캐시 때 운영 DB 부하 |
| **B. 새 요약 테이블을 03:00 수집 때 미리 계산 (채택)** | 홈은 행 몇 개 읽기, 계산 실패 시 어제 값 유지 | 마이그레이션 1회, 스크립트 1개 추가 |
| C. 기존 `refreshRealEstateSummary`(건물 요약) 안에 끼워 넣기 | 단계 추가 없음 | 이미 85분 예산이 빠듯함, 실패 영향 범위가 커짐 |

## 5. 설계

### 5.1 저장: 새 모델 `RegionMarketSummary`

한 행 = 한 지역(전국 / 시·도 / 시군구). 아파트 매매만.

- 지역 키: `scope` (`nation`|`city`|`district`), `citySlug`, `districtSlug` (전국은 둘 다 빈 문자열, 시·도는 districtSlug 빈 문자열) — 유니크 `(scope, citySlug, districtSlug)`. 표시용 `label` ("서울 강남구").
- 평당가: `ppMedian12m` (최근 12개월, 만원/3.3m²), `ppMedianPrev12m` (그 전 12개월), `dealCount12m`.
- 최고가: `topDeals` JSON — 최근 12개월 상위 3건 `{buildingName, bjdCode, dongName, jibun, area, amount, date, canonicalPath}`.
- 거래 증감: `volRecent` (31~60일 전 계약), `volPrev` (61~90일 전 계약), `volWindowFrom`/`volWindowTo` (최근 구간 날짜).
- `computedAt`.

평당가 = `dealAmount(만원) / exclusiveArea(m²) × 3.3058`. 중간값은 앱에서 계산하지 않고 MySQL 윈도 함수 또는 지역별 정렬로 구한다(빌더 판단).

### 5.2 계산 (새 스크립트 `refreshRegionMarketSummary.ts`)

- 대상 거래: `AptSaleTransaction` 중 취소 아님(`cancelDealDay`·`cancelDealType` 둘 다 NULL 또는 빈 문자열 — `homeMarketService.buildWhereClauses`와 같게), **직거래 아님**(`dealType`이 NULL이거나 `'직거래'`가 아님), `dealDay IS NOT NULL`, 면적·금액 유효, 계약일이 오늘(KST) 이전.
- 지역 매핑: 거래의 `(city, district)` → 홈 지역 선택과 같은 slug 체계(`REAL_ESTATE_REGIONS`/`Region`). 서울특별시/서울 혼재, 전남광주통합특별시·광주 분리(`homeMarketService.resolveRegion`의 규칙)를 그대로 따른다. 매핑 안 되는 거래는 시군구 행에서 빠지지만 전국 행에는 들어간다.
- 쓰기: 계산이 모두 끝난 뒤 한 트랜잭션으로 교체. 중간 실패 시 이전 행 유지. 0행이면 실패 처리(쓰지 않음).
- 실행: `scripts/ops/sync-real-estate.sh`의 Summary 단계 다음에 한 단계 추가 (예산 15분, 실패해도 전체 동기화 exit 코드에는 영향 없음 — K-apt 단계와 같은 방식). SyncHistory category `region-market`.
- 거래 테이블은 최근 24개월만 읽는다(어떤 인덱스를 탈지는 EXPLAIN으로).
- 구간 경계(31~60 / 61~90일), 최소 건수(20)는 상수 한 곳에 둔다. 구현 중 로컬 DB로 "계약 후 N일 지나 신고된 비율"(`createdAt` − 계약일)을 측정해, 31일째에 아직 신고가 많이 남아 있으면 경계를 늦춘다(측정 결과를 PR에 적는다).
- 시·도·전국 행은 시군구 결과를 더하지 않고 각자 계산한다(합이 맞을 필요 없음). 지역 키는 홈 지역 선택이 실제로 보내는 (city, district) slug 조합 그대로 만든다 — `resolveRegion`의 광주/전남/통합 규칙을 공용 함수로 빼서 계산과 조회가 같은 규칙을 쓰게 한다.

### 5.3 API

`GET /api/real-estate/home-market` 응답에 섹션 추가 (기존 필드 유지):

- `priceStats`: 선택 지역 행의 `{ppMedian, ppYoyPct, dealCount12m, topDeals[3], computedAt}` — `SectionResult` 형태(`ok`|`error`), 행이 없거나 `dealCount12m < 20`이면 `ok` + `null`(화면에서 줄 숨김). `ppYoyPct` = 최근 12개월 중간값 ÷ 그 전 12개월 중간값 − 1. 그 전 12개월 거래가 20건 미만이면 `null`(변화율만 숨김). 화면 문구는 "1년 전 대비".

새 엔드포인트 `GET /api/real-estate/rising-regions?scope=all|capital|nonCapital`:

- 시군구 행 중 `volRecent ≥ 20` 이고 `volPrev ≥ 1`, 증가율 `(volRecent - volPrev) / volPrev` 내림차순 상위 10.
- 수도권 = 서울·경기·인천. 응답에 `{label, citySlug, districtSlug, ppMedian, volRecent, changePct}` + 기간(`volWindowFrom~To`).
- 증가한 지역이 10개 미만이면 있는 만큼만 (감소 지역은 넣지 않음). 0개면 빈 배열.

둘 다 기존 home-market처럼 짧은 메모리 캐시를 둔다(요약 테이블은 하루 한 번 바뀜).

### 5.4 화면

- `HomeMarketSection.vue`: 건수 카드 아래 "새 줄" — 평당가 중간값, 전년 대비(±, 색은 기존 토큰), 최고가 TOP 3(단지 상세 링크), "{지역} 실거래가 자세히 →"(구 허브 또는 시·도 페이지 링크). 지역 바꾸면 함께 바뀐다.
- 새 `HomeRisingRegions.vue`: 시안 ③ 그대로. 데스크톱 2열 10개, 모바일 5개 + "10위까지 더 보기". 기간 문구는 "{M}월 {D}일~{M}월 {D}일 계약, 직전 30일 대비". 각 행은 `/real-estate/apt-sale/{city}/{district}` 링크. 하단 시·도 바로가기 칩(기존 "인기 지역" 칩 역할) — **데이터와 무관하게 항상 렌더**. 선택한 탭에 지역이 0개면 "이 기간 거래가 늘어난 지역이 없습니다" 한 줄. API 실패 시에는 목록·탭을 숨기고 제목과 칩만 남긴다.
- `pages/index.vue`: 인기 지역 섹션 삭제, `HomeMarketSection` 바로 다음에 `HomeRisingRegions`, 그 뒤 기존 AdBanner. 광고 개수는 그대로.
- SSR로 렌더(크롤러에 보이는 링크). 데이터 실패 시 섹션 숨김(빈 섹션·에러 문구 노출 안 함).
- 출처 문구: "국토교통부 아파트 매매 실거래가 · 직거래·취소 제외 · 일상킷 집계".

## 6. 제약

- 운영 DB 스키마는 배포가 바꾸지 않는다: 마이그레이션을 운영에 먼저 수동 적용(백업 → `migrate deploy`) 후 코드 배포.
- 배포 직후 첫 03:00 전에는 테이블이 비어 있다 → 배포 뒤 스크립트를 한 번 수동 실행. 비어 있는 동안 화면은 새 줄·섹션을 숨긴다.
- 홈 광고 위치는 A안으로 확정, 개수 변경 금지.
- 홈 SSR 캐시(nitro 라우트 캐시) — 배포 후 홈 캐시 퍼지 필요 여부 확인.

## 7. 빌더에게 맡기는 것

- 중간값 계산 SQL 형태(윈도 함수 vs 지역별 쿼리), 인덱스 추가 여부(EXPLAIN으로 판단).
- `topDeals`의 canonicalPath 생성 방식(기존 `attachRealEstateCanonicalPaths` 재사용 권장).
- 컴포넌트 내부 구조, 테스트 분할.

## 8. 빌더 검토 뒤 정리한 것 (작성자 판단, 10/30)

- 신고 지연: 31~60일 구간도 늦은 신고가 남을 수 있다 → 경계·최소 건수 상수화 + 로컬 측정 단계 (5.2).
- 빈 탭·API 실패 시 표시, 시·도 칩 항상 노출 (5.4).
- 시·도·전국 행은 독립 계산, 시군구 합과 일치 불필요 (5.2).
- "전년 대비" = 직전 12개월 중간값 대비, 문구 "1년 전 대비", 표본 부족 시 숨김 (5.3).
- 광주/전남/통합 slug 규칙은 `resolveRegion`에서 공용 함수로 분리해 재사용 (5.2).
- 취소 조건은 NULL·빈 문자열 둘 다, 계약일 모르는 거래(`dealDay` NULL) 제외, ops 스크립트 경로는 `scripts/ops/` (5.2).
