# 오늘의 이슈 — 정책 브리핑 트랙 P3 운영 러너북

작성일: 2026-07-07
전제: P1(#523)·P2(#524) 모두 develop 머지 완료. P3는 **새 코드 거의 없음 = 운영 검증** 위주.
성격: SSH·서버 env·어드민 조작이 많아 **사용자 직접 실행 구간**이 큼. 각 단계에 "누가"를 표기.

---

## 0. 전체 그림

```
[0] 프리플라이트(서버 env·툴 확인)  ← 사용자
      ↓
[1] 라이브 정책뉴스 API 필드 실측     ← 사용자(서버) + 나(결과 판단·필요시 수정 PR)
      ↓ (필드 어긋나면 policyBriefingClient 매핑 수정 PR → develop)
[2] develop → main 승격 PR           ← 나(PR) + 사용자(머지)
      ↓
[3] Cafe24 배포(Actions 자동)         ← 자동 + 사용자 확인
      ↓
[4] 라이브 검증(생성→검토→발행→공개)  ← 사용자(어드민) + 나(HTML/SEO 확인)
      ↓
[5] 마무리(사이트맵·RSS·모니터링)      ← 나 확인
```

**핵심 안전장치**: 정책 API 필드가 실제와 다르면 `parsePolicyResponse`가 전부 걸러 **"생성 안 됨(무저장)"** 으로 끝납니다(fail-soft). 즉 **깨진 글이 나오는 게 아니라 아무것도 안 나옴** — 발행 전 draft 단계에서 안전하게 걸러집니다.

## [0] 프리플라이트 — 서버 환경 확인 (사용자)

Cafe24 서버 SSH 접속 후 백엔드 디렉터리에서 확인:

- [ ] **`OPENAPI_SERVICE_KEY`** 설정돼 있나 (정책뉴스 API용, 부동산 등 기존 API가 쓰는 그 키)
  - 확인: `grep OPENAPI_SERVICE_KEY .env` (값이 있으면 OK)
- [ ] **정책뉴스(15095335) 활용신청 승인** 됐나 (data.go.kr 마이페이지 → 활용신청 현황 = "승인")
- [ ] **`OPENAI_API_KEY`** 설정돼 있나 (글 생성용, 기존 뉴스 생성이 쓰는 것)
- [ ] **`cwebp` 또는 `convert`(ImageMagick)** 설치돼 있나 (썸네일 인코딩용)
  - 확인: `which cwebp convert`
  - ⚠️ 과거 미설치로 PNG-as-webp 버그 이력 있음. 없으면 `generateThumbnail`이 throw → 정책 글도 생성 중단됨. 기존 뉴스/가이드가 썸네일을 만들고 있다면 이미 설치돼 있을 것

> 이 4개가 다 OK면 정책 생성이 서버에서 동작할 조건 충족.

## [1] 라이브 정책뉴스 API 필드 실측 (사용자 실행 + 나 판단)

**왜**: `policyBriefingClient.parsePolicyResponse`는 문서 기반으로 `NewsItem`/`NewsItemId`/`DataContents` 등을 가정. WAF로 명세 자동추출이 안 돼 **실제 응답 형태 1회 확인 필요**. 어긋나면 매핑만 조정.

**방법 A (권장·가장 안전) — 서버에서 실제 생성 1회 돌려보기:**
```bash
# 서버 백엔드 디렉터리에서 (dist 빌드 후)
npm run generate:article -- --track policy
```
- 로그에 `[policy] 선정: "..." → subscription / "..."` 나오고 draft 저장되면 **필드 매핑 정상** ✅
- 로그에 `[policy] 적합한 신규 정책 후보 없음 — 무생성 종료` 만 반복되면:
  - (a) 정말 최근 정책이 포커스 카테고리에 없거나
  - (b) **필드 매핑이 어긋나 파싱 0건** 가능성 → 원인 구분 필요

**방법 B — 파싱 원인 구분용(선택):** 임시로 원응답 로그를 찍어 `NewsItem`/`DataContents` 키가 실제 있는지 확인. (별도 진단 스니펫이 필요하면 내가 만들어줌)

**결과 처리:**
- 매핑 정상 → [2]로.
- 매핑 어긋남 → 실제 필드명 알려주면 내가 **`policyBriefingClient.ts` 매핑 수정 PR**(→ develop) 만들고, 테스트 갱신 후 다시 [2].

> 실측은 **[3] 배포 후 서버에서** 해도 됨(오히려 프로덕션 키·환경 그대로라 정확). 그 경우 순서는 [2]→[3]→[1]→[4]. 단 그땐 draft만 만들고 **발행은 [1] 통과 후**.

## 롤백 / 리스크 노트

- **정책 글이 이상하게 나옴** → 발행 안 하고 draft에서 반려/삭제. 공개 영향 0(draft는 비공개).
- **필드 매핑 어긋남** → 무생성(fail-soft)이라 사고 없음. 매핑 수정 PR로 처리.
- **썸네일 실패** → 정책 글 생성 자체가 throw로 중단(부분 저장 없음). cwebp/convert 설치 문제이므로 [0]에서 선확인.
- **DB 컬럼**: `sourceExternalId`는 nullable 추가라 기존 데이터 무영향. 롤백 시에도 안전.
